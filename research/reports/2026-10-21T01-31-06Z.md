# Moyu as an upstream for restraint and evaluation design

Moyu is worth retaining as a research upstream at medium priority. Its useful contributions are concrete scope-drift examples, a short restraint-prompt comparison, and tasks checking that restraint does not suppress requested work. RSP already has substantial mechanism-admission, test-value and preservation rules. This inspection supports focused research questions, without establishing a need to strengthen or replace those rules.

## What the source adds to the research questions

### Compare a complete Skill with a short restraint instruction

The [benchmark conditions](../captures/moyu@f276e3cc8a7f/benchmark/conditions/baseline-concise.txt) include a short instruction to minimize changes and avoid unrequested additions. This is an active restraint treatment, not an instruction-free baseline. The current [runner](../captures/moyu@f276e3cc8a7f/benchmark/runner.py) also lists a distinct `neutral` condition; the retained analysis contains five conditions and does not include that neutral arm. The [control](../captures/moyu@f276e3cc8a7f/benchmark/conditions/control.txt) requests completing the task. The older pilot's robustness-oriented control is described separately in [results.md](../captures/moyu@f276e3cc8a7f/benchmark/results.md), which acknowledges that pilot's verbosity bias. These controls should not be conflated.

The retained [analysis.json](../captures/moyu@f276e3cc8a7f/benchmark/results/analysis.json) reports the following A-type comparisons, where reduced additions were expected:

The conversational assessment's reference to p approximately 0.73 therefore applies specifically to code lines. These are inspected upstream outputs; no statistics were recomputed and no experiments were reproduced.

RSP's inspected quality matrix tests the complete seven-Skill suite and explicitly disclaims causal attribution. It has no matched short-instruction arm. A useful future question is whether the complete suite adds value beyond a brief restraint instruction while preserving correctness, required evidence and completion. Such a comparison would need matched tasks, model settings and authority boundaries. This report neither designs an executable evaluation nor authorizes one.

### Recognize drift while work is still in progress

The [standard Skill](../captures/moyu@f276e3cc8a7f/skills/moyu/SKILL.md) names recognizable signals: whole-file rewrites for small requests, incidental formatting changes, speculative abstractions, new dependencies and cascading repairs. Its L1 through L4 interventions turn a broad preference for simplicity into possible moments of self-correction. The [lite](../captures/moyu@f276e3cc8a7f/skills/moyu-lite/SKILL.md) and [strict](../captures/moyu@f276e3cc8a7f/skills/moyu-strict/SKILL.md) variants expose how much intervention policy can change with instruction strength.

RSP already requires the smallest complete implementation, evidence for added mechanisms and safe continuation within unchanged authority. Core's convergence method also bounds repeated correction. The narrower research opportunity is behavioral: can an agent notice an emerging unjustified expansion and remove its own unnecessary work before delivery? The inspected matrix primarily judges resulting artifacts and evidence; it does not isolate the timing or effectiveness of that recognition.

A future case could distinguish unnecessary expansion from a necessary collaborator change, and preserve unrelated pre-existing edits during recovery. File counts and diff size could trigger inspection, but cannot decide whether the work exceeds authority. The source inspection supplies no measured evidence that Moyu's escalation levels improve this behavior.

### Check completion as well as restraint

Moyu includes tasks explicitly requesting [context-manager refactoring](../captures/moyu@f276e3cc8a7f/benchmark/prompts/s9.txt), [public-function documentation](../captures/moyu@f276e3cc8a7f/benchmark/prompts/s10.txt), and [unit tests](../captures/moyu@f276e3cc8a7f/benchmark/prompts/s11.txt). Its [mixed task](../captures/moyu@f276e3cc8a7f/benchmark/prompts/s12.txt) combines a bug fix with a new bulk operation. These are useful counterexamples to treating every addition as a failure.

RSP already pairs protocol simplification with necessary mixed-protocol preservation, and redundant capture identity with necessary external digest validation. Preservation controls are therefore an existing strength, not a newly discovered missing principle. Further research could cover a user request that requires modifying an unnamed collaborator, a required regression test, or an explicitly requested document. Judge whether the agreed outcome is complete and whether existing authority permits proceeding. Avoid making repeated permission requests the rewarded behavior.

## Limits on transfer

The standard Skill frequently equates scope with files explicitly named by the user and discourages tests or documentation unless requested. Strict mode requires confirmation before editing and imposes a 20-line cap for small changes. The standard delivery checklist also asks for removal of lines whose deletion does not interrupt functionality. Transferred literally, these rules could suppress regression protection, preserve incomplete fixes or interrupt work already authorized by outcome.

RSP's current Implement and Review methods instead ask for production consumers, material consequences, distinct regression value and maintenance cost. They permit necessary tests and comments, recognize different responsibilities behind similar code, and judge decomposition by caller and maintainer burden. Keep those distinctions. The upstream's signals may help select inspection targets; they do not justify automatic rollback, universal approval steps, numeric diff limits or another workflow Skill.

The [metric extractor](../captures/moyu@f276e3cc8a7f/benchmark/metrics.py) sums positive changes in docstrings, try blocks, raises and type checks, plus new imports and files. Most code-volume and AST measurements read `app.py`, rather than aggregating all generated modules. The [lint detectors](../captures/moyu@f276e3cc8a7f/linter/signals.mjs) similarly score new declarations and use fixed file-count or error-handling-ratio heuristics. These are diagnostic signals, not semantic judgments about necessity. A required validator or API comment can increase the score. Its [README](../captures/moyu@f276e3cc8a7f/linter/README.md) documents report-only mode as the default threshold; retaining its code for research does not install a CI gate.

The runner supplies two Python files and a task to a model API, then extracts complete modified files from one response. It does not exercise a persistent coding agent navigating a repository and responding to tool failures, user corrections or shared-worktree changes. The benchmark has functional tests, including an [S11 check](../captures/moyu@f276e3cc8a7f/benchmark/tests/test_s11.py) that generated tests exist and run; that is not by itself proof that those tests discriminate meaningful regressions. Smaller output and successful sample tests cannot establish general maintainability or live-agent effectiveness.

## Retained conclusion and evidence limits

Keep Moyu registered for its evolving restraint examples, experimental controls and heuristic implementation. The strongest follow-up question is the incremental value of complete guidance over a short baseline. Execution-time drift recognition and complete authorized work provide additional behavioral questions. Existing RSP admission and preservation rules remain the local baseline; this investigation identifies research opportunities rather than confirmed product defects.
