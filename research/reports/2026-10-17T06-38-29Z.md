# Bounded evidence reading and first-call check receipts

Two offline validations support smaller evidence reads and explicit first-call check
results without reducing required verification. The retained stop/continuation chain
can be reconstructed from selected native observations, and an isolated check exposes
its own success/failure without a second run to recover its exit status. No new model
or judge ran; this is not an observed improvement in model behavior or token cost.

WorkRef: evidence-reading-regression.

## First-call exit attribution

The existing correction-continue source/check are copied to local disposable
workspaces. The passing variant matches the repaired source preserved in the original
trial byte-for-byte; the failing variant matches its captured initial source. Neither
check code nor task acceptance instructions are changed.

| Source variant | Original-style batch exit | Isolated implementation check | Isolated reviewer check | Following git status |
| --- | ---: | ---: | ---: | ---: |
| Original failing source | 0 (failure masked) | 1 | 1 | 0 |
| Retained repaired source | 0 | 0 | 0 | 0 |

The original-style comparison is node tools/check.mjs followed by git status --short
with a semicolon. Git success determines the batch status even when Node's assertion
fails. Separately executing the check provides its own exit code and output on the
first execution; the following status command cannot overwrite that evidence.

The proposed separated path executes one real check for each required role and has
no retry. The comparison adds one mixed-batch control per source variant; those
control executions are not hidden. Both roles are exercised against both variants
for diagnostic comparison. The negative probe is not an instruction to dispatch a
reviewer after failed implementation, and role labels do not certify native worker
independence. Existing natural/continue independent-execution requirements remain
unchanged. Original passing check evidence still cannot replace a separately required
reviewer execution; a role change alone creates no additional rerun beyond that duty.

[Retained receipts][receipts] contain all stdout/stderr and exit codes, including the
expected assertion failures. The test runs trusted local fixture commands, never
commands taken from captured tool-input strings. Workspace Git operations are local
initialization/status only; no maintainer Git state is changed.

## Validation and correction boundary

The four focused tests passed, covering positive/negative evidence selection and both
check source variants. Final full-suite, lint, documentation and preservation results
are in the [verification summary][verification]. Initial lint formatting failures

The demonstrated local changes are how the consumer reads evidence and how a check
result is collected, not weaker acceptance rules. A targeted reader should preserve

projection service, runtime command wrapper, global prompt rule or new model experiment
was introduced. Future executor behavior and actual cost savings remain unverified.
