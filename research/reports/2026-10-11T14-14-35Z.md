# Shared work identities, suite installation and structural Review

The user authorized the suite proposal, preservation of existing work, local checks
and a matched model comparison. This is candidate-bound evidence, not a release,
independent review of the RSP implementation or a claim of general model stability.

## Candidate and baseline

The baseline is the dirty authored Skill corpus retained before this implementation
in tests/skills/reports/suite-baseline-20261011T133434Z/skills. Its sibling patch and
head record preserve the starting state. Earlier routing, host-metadata and WorkRef
repairs remain included. No upstream code or instruction asset was copied.

The candidate installs the seven core Skills together, allows direct invocation,
centralizes runtime work identities in rsp/references/work-model.md, and moves
structural discovery from a separate Audit entry into Review's conditional method.
It rejects partial installation, keeps protected migration/rollback, and validates
Core references inside the installed suite. Old audit identities migrate to Review.

Primary baseline: tests/skills/reports/2026-10-11T13-48-41.612538Z.
Primary candidate: tests/skills/reports/2026-10-11T13-48-41.624024Z.
Both arms have byte-identical task/support/model-catalog snapshots, one attempt per
task and per-job concurrency one. Both use Codex 0.162.1 and AI-HUB/gpt-6.1-sol at
medium effort; semantic judges use the task-defined high effort. Both share the
same evaluation image and CLI; this isolates Skill changes, not CLI versions.
Installation changes are covered by code and actual packed-install tests.

## Observed loading

In the primary candidate, the shared work-model body appears once in each of the
three tracked completion contexts and the Verify context. These contexts load
Review or Verify directly, then the Core reference, without loading Core's entry.
Untracked structural review, delivery assessment and coordination workers do not
load the shared work model unnecessarily. Both structural tasks select Review,
structural-review.md and code-review.md; the baseline selects the old Audit entry
and structural-lenses.md. Thus fewer entrypoints does not imply fewer method bytes
on a structural review: the general Code method is also loaded in this sample.

Across the 10 retained sessions per arm, no complete instruction resource repeats
inside a session and no decoded model-facing tool result is truncated. Different
workers' first reads are separate context needs, not duplicate reads in one
context. Full-source presence is a diagnostic, not a proof of comprehension or
exhaustive detection of repeated partial reads.

After the primary snapshot, a duplicate identity definition in Core's conditional
groups-dependencies.md was replaced with a direct shared-model link, retaining
Group operations. No primary session loads that resource or explicitly reads it
in an instruction command. Primary evidence is reused for unchanged observed
branches; the follow-up snapshots the exact final Skill corpus. This does not
claim model coverage of every Group lifecycle operation.

## Executor usage

Harbor 0.24.0's native adapter selects the lexical latest session file for a task,
which can be a child. RSP now identifies the parent from thread.started and counts
retained descendants through session_meta.source.subagent.thread_spawn parent
links, deduplicating identities. Unknown totals remain unknown, and parent-only
pricing is not presented as aggregate cost. Native trajectory conversion uses the
identified root. Judge usage remains outside these totals.

The nested thread_spawn variant was confirmed against actual retained logs after
the primary jobs began. Their original native results and saved inputs remain
unchanged; the figures here and regenerated summary use corrected offline
aggregation. This reporting repair does not rerun agents or reinterpret verdicts.

## Acceptance and remaining limits

Within these cases, shared definitions load correctly and structural discovery,
completion judgments, authority restraint and independent verification show no
semantic regression. The original report-format failure remains part of the
evidence; clearer task instructions pass a fresh matched retry without weakening
validation. The suite reduces independent entrypoints and definition ownership,
not necessarily loaded bytes or total cost.

This is one attempt per arm, plus one clarified grouped retry and a direct Commit
probe. It is not broad stability or full release acceptance. Tracked Shape/Doc
workflows and Group lifecycle operations were not newly model-tested here. The
structural branch currently loads both structural and general Code methods; any
further reduction should be a separate outcome-preserving comparison, not a
conclusion drawn from token counts alone. No commit, archive, push or publication
was performed in the maintainer checkout.
