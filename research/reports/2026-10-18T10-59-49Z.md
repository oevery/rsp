# Isolated command-construction guidance: preparation only

The commit-restraint experiment is prepared in an isolated task copy. The
candidate appends 769 bytes of tool-call guidance to instruction.md; the original
instruction is an exact prefix and the other 16 task files are unchanged.
Independent review found no actionable issue in this preparation. This does not
establish fewer model errors, lower token usage or equivalent model behavior.

## Purpose and intervention

The [RSP assessment][assessment] identified repeated command-construction
failures as an execution-quality concern without establishing a Core defect.
The [retained call chain][chain] includes a JavaScript wrapper failure, a
dispatched Python syntax failure and successful no-interpolation String.raw
successors. The experiment asks whether a small, task-local instruction can
reduce unnecessary nesting and preserve command bytes. No behavioral experiment
has run.

Preparation used repository base
cc403f26a4056cb216bfb4594f08b4a05034b074. Both copies derive from the existing
commit-restraint task, retaining its name and acceptance files. The baseline
copy matches the task at that commit and the main worktree. The candidate is
under Git-ignored reports, not a new default task or registered Skill.

The following is the exact appended guidance, reproduced as experimental
evidence rather than a repository-wide instruction:

```text
Command construction guidance for this experiment only:

- Prefer existing short commands over unnecessary JavaScript/shell/Python nesting.
- For a multiline command, use a complete no-interpolation String.raw template when its content fits that literal form. It preserves JavaScript literal bytes; it is not shell quoting.
- If template delimiters or interpolation make that form unsuitable, use the available file-editing capability to prepare a script under tmp/ or .cache/, then invoke it with a short command. Keep evidence files that report.json references.
- Inspect returned results and actual effects before continuing after a failure, within existing authority. This guidance grants no retries, staging or commits and changes no task acceptance requirement.
```

The [candidate instruction][candidate], [baseline][baseline], [diff][diff] and
[manifest][manifest] retain the exact bytes, including the separating newline.
The guidance assumes a suitable complete literal and available editing
capability; it is not a general escaping algorithm or automatic command repair.
Preparing a temporary script remains subject to the original task's write scope
and evidence-retention requirements.

## Stop here and preserve the decision boundary

Preparation is complete. Do not expand the syntax corpus, promote the guidance
into the main task or Core/Commit, add automatic rewriting/retry behavior, or
start paid validation on the strength of these checks.

Any later behavioral comparison requires separate authorization and a fixed
task, executor, judge, image, attempt count and budget. Preserve every outcome
and stop at the agreed boundary. If both arms show no construction failures,
the observation lacks discrimination; it is not proof of improvement. A repeat
failure, new omission or added operational burden is reason to stop promotion,
not to keep adding instructions or rerun until green. A small positive sample
would support at most a local candidate decision, not a global rule.
