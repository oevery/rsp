# Recovery reference loading: one live before/after pair

Both original-task interruption-recovery runs passed with reward, checks and
judge scores of 1.0. The baseline explicitly read focus-continuation.md; no
candidate read of that body was observed. Both retained safe cessation and
continuation. This is local evidence for the intended loading branch, not
proof of lower total rule burden, causal efficiency or repeated reliability.

## Actual loading and recovery safety

In baseline parent session 01a14fa3-3b85-7b83-9b5c-f4c1c4f47490, line 19
reads coordination.md, coordination-recovery.md and focus-continuation.md.
Candidate parent 01a14fa7-c707-77f0-a720-a1bbf1814039, line 19, reads the
first two plus rsp-implement/SKILL.md instead. Both arms' workers load their
own Implement Skill. The [loading observations][loading] retain source
hashes, command locations and full-text comparisons.

Across root and child sessions, recognized explicit concrete-path cat reads
of Skill Markdown total 42,170 source bytes for baseline and 50,077 for
candidate. Candidate avoids the Focus body but adds a parent Implement read
alongside the revised recovery text. This pair therefore does not demonstrate
a net decrease in explicit rule-source volume. The observation does not
account for all injected, implicit or compressed model context, and source
bytes are not delivered tokens. No universal absence of Focus loading follows.

The [behavior audit][behavior] locates original begin-command exit 0,
first-worker native completion, parent observation of completion and only
then distinct continuation dispatch in both arms. Resume runs once, finishes
with exit 0 and is awaited. Final artifacts contain A then B exactly once,
correctionCount 1, completed true and paused events as an unchanged prefix.
Both final reports exist. These observations support same-session recovery
safety for the tested contract; actual Capsule and cross-session behavior
were not newly exercised. Their earlier evidence remains static, not promoted
to live acceptance by this task.

Lower candidate tokens and elapsed time coexist with different loading and
command workloads, baseline construction failures, cache histories and fixed
execution order. A single pair cannot attribute those differences solely to
the reference change. The narrower supported result is that this candidate
omitted the Focus body while satisfying the original recovery task.

## Judge retry and usage limits

The fixed image retains harbor-rewardkit 0.2.2 and its
_MAX_JUDGE_RETRIES = 3 loop. The inspected judge-source SHA256 is recorded
in the execution freeze. This policy is distinct from Harbor task retries.

Native final judge scores are available, but the retained details expose no
exact format-attempt counter or judge usage. All seven gateway observer
invocations failed with FileNotFoundError because ocx was unavailable in the
host PATH. The [judge observations][judge] therefore contain no correlated
gateway requests or usage. Empty observations do not mean zero retries,
zero requests or zero cost. Actual internal format retry counts and judge
tokens remain unknown; policy inspection establishes only the unchanged limit.
The observer failures are retained separately and are not executor retries.

## Preservation and stop boundary

The [final integrity check][integrity] confirms 48,656 historical files,
1,465 tracked sources and both 71-file frozen input sets unchanged after
execution, with the pinned image identity retained. All original outcomes,
failures, trajectories and snapshots remain available. Two post-run
orchestration parse rejections and an unmatched observation-file glob remain
in observation-limits.json, separate from native execution failure counts.
They caused no model dispatch or native result change.

Independent evidence review, document consistency review and mechanical/
preservation checks are retained in the [review directory][review]. These
reviews do not add behavioral trials or recover unavailable judge telemetry.
No prior isolated guidance candidate is adopted or modified, and calibration
labels remain candidate. No Core/Commit entrypoint or scoring rule is changed
by recording these results.

Stop after this pair. It supports the intended local loading choice and
retained task completion, while total rule burden and causal efficiency remain
unproven. There is no automatic supplement, broader recovery acceptance or
release decision. Raw evidence links are private and Git-ignored; a fresh
clone without those artifacts cannot independently reconstruct this audit.
