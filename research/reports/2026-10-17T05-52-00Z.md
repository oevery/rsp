# Command construction: retained failures and offline regression

Five retained trials contain seven command-construction failures: five JavaScript
wrapper parse failures and two Python heredoc parse failures. All seven reproduce
at their observed first layer without executing captured code. Five distinct
successful successor calls parse. No independent shell syntax failure was observed.
This identifies the caller's tool-input construction as the narrow correction
boundary; it does not establish an RSP CLI or Harbor adapter defect.

## Classification and provenance

The classifier correlates root and descendant session call/results, not only the
commands rendered in codex.txt. A wrapper parse failure produces no shell-command
event and is otherwise easy to miss. It counts direct structured exit results but
does not recursively reinterpret their stdout as more tool results: reading a file
containing an old error must not count that historical error again.

Expected exit 73 is classified using the exact failure-task contract and preparation
call, not a blanket rule that exit 73 is harmless. The early ls failure is retained
separately from encoding. Parser errors in the analysis itself and lint findings
are also separate from the native observations.

The five JavaScript failures comprise four ordinary quoted strings containing raw
line breaks and one incomplete source ending at a cmd property. Both Python failures
have valid outer JavaScript and shell syntax, but the cooked command contains a
physical newline inside a Python quoted literal. The original wrapper containing
the failed baseline write also dispatched a worker afterward: a returned exit code
is data, not an automatic JavaScript exception. This report does not claim the whole
call was side-effect-free, or infer a new prerequisite violation without establishing
its actual dependency. It is another reason not to replay captured calls.

The prior natural/commit/interruption result reports retained source trajectories
but did not enumerate all pre-shell wrapper failures. This report supplements their
cost/failure diagnostics; it neither replaces those files nor changes their verdicts.
In particular, interruption-recovery has four construction failures, not only the
two Python errors described in its earlier command-level summary.

## Offline regression and smallest correction position

The [regression][test] compiles the exact JavaScript as an uninvoked async function,
decodes literal cmd values with the installed TypeScript parser, checks shell syntax
with bash -n and parses quoted Python heredoc bodies using compile without exec.
It never calls a captured tool, evaluates its JavaScript, runs its shell/Python body,
spawns a worker or touches task Git state. Startup hooks are excluded from syntax
subprocesses. All selected literal cmd arguments and Python heredocs are inspected;
this is a bounded corpus check, not a general shell analyzer.

All seven failures reproduce at the expected first layer; all five historical
successors pass syntax checks. Successors sometimes changed the inspection method,
so this is syntax evidence, not proof of semantic equivalence. Two additional
controls repair only the malformed Python escape in a copied command, serialize that
command as a JavaScript argument and assert that decoded bytes equal intended bytes.
Both then parse through Python. JSON encoding here constructs a JavaScript literal;
it is not shell quoting and is not inserted into a shell command for execution.

The smallest demonstrated intervention is at the executor's construction of tool
arguments: complete the JavaScript source and preserve the intended command bytes
across the outer literal. The owned RSP diagnostic correction is to include wrapper
failures in evidence summaries. Current Core already requires inspecting prerequisite
results; Commit already protects exact snapshots and one-attempt delivery. Neither
needs weakening or an extra encoding-prompt layer on this evidence. No runtime helper,
automatic rewrite/retry mechanism, adapter fix or prompt change was introduced.

## Validation and remaining limits

Focused syntax regression passed. Final repository validation and source/evidence
preservation results are in the [verification summary][verification]. Original failed
calls, expected failures and the initial lint failure remain retained alongside passes.
No new behavioral acceptance or measured cost saving follows from compile-only checks.
The corpus covers these observed literal forms, not arbitrary shell grammar or every
host tool representation. It cannot identify why a model generated incomplete source,
prove a provider truncation cause, or predict whether a future model will avoid it.
