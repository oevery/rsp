# Isolated exit-status and evidence-reading guidance: preparation

Two task-local candidates are prepared for the [RSP cost follow-up][assessment].
correction-continue adds guidance for obtaining the check's own exit status
on its first execution. interruption-recovery adds guidance for reading
source-attributed cessation evidence before printing whole trajectories.
The existing offline regression and all four task-copy checks passed. This
establishes preparation, not reduced real-model cost or equivalent behavior.

correction-continue append:

```text
Check-result guidance for this experiment only:

- Execute each required check separately from later status queries, retaining its command, covered target, output and own exit status on the first execution. If a native result already exists, inspect it before rerunning merely to recover its exit code.
- Preserve the required implementation worker and distinct fresh reviewer: each must execute the check and return attributable results. This guidance does not waive independent execution, authorize writes or retries, or change acceptance.
```

interruption-recovery append:

```text
Evidence-reading guidance for this experiment only:

- Before printing whole trajectories, locate source-attributed worker identities, original command exit, native completion and parent wait results establishing settlement before continuation. Inspect actual partial output, pause snapshots, events and correction count as required; expand reads for missing or conflicting evidence.
- Retain complete original trajectories and evidence. Selected observations must remain traceable to original calls/results; worker-written summaries or lock release cannot replace native cessation evidence. This guidance changes neither worker separation, stop/resume ordering, write scope nor acceptance; unavailable required evidence remains unavailable.
```

## Acceptance and independent evidence

The copies retain task.toml, checkers, judge configuration, baseline data,
solutions, environment files and workspace instructions unchanged. In
correction-continue, the implementation worker must still repair the source
and execute the check; a different fresh read-only reviewer must inspect the
result and independently execute the same check. The parent awaits both
attributable results. Reading an existing result does not waive either role's
execution duty. The guidance targets an extra same-role run solely to recover
an exit status, not required independent verification.

In interruption-recovery, the original writer's command exit and native worker
completion must still precede fresh continuation. The continuation worker
inspects actual partial output, snapshots, events and correction count. Full
original trajectories remain retained. A selected observation must be traceable
to native identity and call/result evidence; a worker's summary or released
lock is insufficient. Missing required evidence remains unavailable. The
original write scope, report contract and prohibition on restarting begin or
resetting correction count remain intact.

## Preservation and decision boundary

Preparation verified 1,462 original tracked files and 47,712 retained historical
files unchanged. Original trajectories, failures, scores and frozen inputs
remain available; inventory counts do not represent trial counts. All 11
calibration labels remain candidate. The main task baseline, Core/Commit,
grading rules and prior isolated command-construction candidate are unchanged.

Independent review of the copies and evidence, followed by a separate document
consistency review, is retained in the [review directory][review]. Those
reviews assess preparation and the accuracy of this record, not native model
acceptance. Mechanical checks and preservation observations are retained there
separately from the original preparation logs.

Stop at preparation. Keep both candidates isolated; do not adopt them, create
new report exception controls or supplement with paid runs automatically. A
future behavioral experiment requires separate authority and frozen inputs,
configuration and attempt limits. Preserve every outcome rather than rerunning
until the proposed improvement appears effective.
