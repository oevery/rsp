# Promptfoo and Harbor: executed framework selection

Select **Harbor 0.24.0 as the main project and Skill evaluation framework**. Promptfoo 0.124.0 also passed this capability probe and is a credible lighter alternative for local CLI evaluation. Harbor wins this selection because it owns separate verification environments, declared artifact restoration and source-linked regrading. The result is not evidence that Harbor produces better model answers or is statistically more reliable. Do not combine both orchestrators in the production evaluation path.

## Scope and evidence

The clean RSP candidate was `5c085c45a287df89b139f45545394fd5d0d30079`. The historical Implement Skill baseline was `47a5231f9bcbd637440af16fe58be784686df472`. Both frameworks used the same task content, repository Skills, deterministic verifier and actual local OpenCodex CLI `0.150.1`, with executor `AI-HUB/gpt-6.1-sol` at medium effort. The independent document assessment used the same model at high effort in a separate read-only session. Node was `24.21.0`; Docker Server was `29.4.0`. Registry queries confirmed the two pinned framework package versions before installation.

Private artifacts, source fixtures, probe callbacks and machine-readable observations are retained in [the experiment directory](../../tests/skills/reports/framework-comparison-20261007T160027Z/). [The result summary](../../tests/skills/reports/framework-comparison-20261007T160027Z/results-summary.json) cross-checks scores, recovery identities, model sessions and the semantic verdicts. These files are ignored and are not backed up by committing this report. No credentials or private provider endpoint values are included here.

This was an authorized direct evaluation, not an implementation of the new production test system. The existing test runner, project configuration and upstream acquisition system remain unchanged. One shared helper reused the existing isolated OpenCodex process adapter; it did not invoke the old matrix runner or its scoring pipeline. Framework-specific probe callbacks were 14 lines for Promptfoo and 22 lines for Harbor, excluding the common helper and verifier. These small counts describe this probe, not a forecast of complete migration effort.

## Executed tasks

Each framework completed four accepted live samples:

1. Current Implement Skill: repair an integer-cent subtotal/discount/shipping calculation.
2. Current Implement and Doc Skills: repair that calculation and update its usage documentation.
3. Real RSP production source: restore normalized duplicate-issue rejection in `src/core/issue-relationship.ts`, retain valid relation and unsafe-URL behavior, and write a maintainer note. The fixture came from the candidate Git commit with one explicit defect overlay. This exercised a production module, not a complete application deployment or the full RSP suite.
4. Historical Implement Skill: execute the same calculation task with the previous Skill package. The task and verifier remained unchanged.

For the production-module task, Node's experimental TypeScript transformation executed the actual resulting source. That method was common to both frameworks. The synthetic fixtures required no installed application dependencies. Final Git status showed changes confined to the requested module and, where requested, documentation. User notes were preserved. The tested Git index began without staged changes; this probe does not establish preservation of a complex pre-staged index.

## Failures and operational differences

Initial integration failures were resolved and retained rather than counted as model failures. The local execution adapter rejected a workspace beneath an ancestor containing project Codex configuration, so execution was moved into a temporary isolated directory. Copying Git's read-only object files back into a retained workspace then failed after some Agent executions; copying task artifacts while retaining the existing Git metadata resolved that adapter problem. Harbor's first verifier fixture also lacked Bash and used the wrong restoration path. The final verifier image supplies Bash; declared artifacts are restored to their original `/app` source path. A preliminary judge invocation lacked a Git repository and was refused before model execution; the final read-only assessment used a disposable initialized repository.

Two significant default behaviors were demonstrated:

- Promptfoo `eval --retry-errors` updated the same evaluation and rewrote the original configured JSON export. A separately provided output flag did not preserve the earlier export in this probe. The selective-recovery experiment explicitly copied its original export first.
- Harbor `jobs resume --filter-error-type RuntimeError` removed the failed Trial directory before rerunning it. It preserved the successful Trial. The probe retained the failed Job material separately before that operation. Harbor does not automatically preserve every failed attempt under this recovery method.

Harbor's initial injected-fault summary displayed mean reward **0.500** for one successful task and one infrastructure exception. Its separate exception count was available, but that mean must not be presented as model task success rate. A production summary must show scored outcomes and infrastructure errors separately, including the denominator. Promptfoo's output distinguished one pass and one error directly.

Promptfoo's standalone regrading was materially simpler than the earlier discussion assumed. A saved output can identify the retained workspace, and a JS assertion can recheck it without a model call. However, workspace creation, retention, the pointer contract and portability remain adapter responsibilities in this approach. Harbor's artifact declaration and regrade command handled container restoration and emitted source-linked results directly.

## Selection and adoption boundary

Harbor is preferred for RSP's stated long-term project-testing goal. Preserve Vitest for deterministic code tests. Use one Harbor execution path for single-Skill and mixed tasks, deterministic task verifiers where sufficient, and semantic grading only for requirements that need it. Use the native records rather than adding another result registry. Promptfoo remains a viable replacement candidate if the project later prioritizes host-only CLI iteration over managed project environments; it is not needed as an outer wrapper or dashboard for Harbor.

Before adopting Harbor, resolve these concrete integration obligations in the migration itself:

- Preserve unsuccessful attempt evidence before a recovery command that removes it; keep regrades as separate results.
- Report task failures, infrastructure exceptions and unavailable evidence separately. Do not use the default mean as the acceptance summary.
- Wire actual model/version/effort, token usage and trace navigation into native Agent context. Keep unavailable billing information explicitly unknown.
- Select the final Agent placement deliberately. This probe ran the actual local OpenCodex Agent on an isolated host workspace, transferring it into and out of Harbor containers. Separate Docker verification and artifact regrading were real, but the Agent itself did not execute inside the container. Containerized Agent parity and native Skill-injection APIs were not validated.
- Retire the old matrix orchestration after the selected task coverage has migrated; do not keep two full evaluators behind a new wrapper.

The probe did not measure long-run reliability, stress concurrency, SIGINT cancellation cleanup, multi-service applications, native subagent behavior, viewer usability, remote workers or publication workflows. Temporary workspaces and retained results are local evidence, not a cross-device recovery guarantee. Initial adapter repairs were performed by the same implementer, and the document judge was not an independent infrastructure audit. These limits constrain reliability claims; they do not erase the demonstrated task execution, selective recovery and regrading capabilities.
