# RSP reliability, execution cost and rule burden

The retained evidence supports keeping RSP's core authority and recovery
boundaries. The strongest remaining execution-quality concern is repeated
command construction failure. Smaller evidence reads and fewer fragmented
acceptance cycles are plausible cost improvements; neither a broad Core rewrite
nor additional rules is justified by these observations. This assessment closes
the bounded inspection, not the remaining reliability questions.

## Focused follow-up: evidence consumption and check reuse

The retained traces support two concrete avoidable operations, not a measured
share of overall execution cost. In the [interruption continuation session][read-session],
line 17 requests the complete first-worker trajectory alongside state files;
line 24 then selects identities, calls and completion events from that same
trajectory. The 102,087-byte first-worker file is the requested source size,
not a measured number of tokens delivered to the model. Output limits and
other files in the call prevent equating it with actual context consumption.

In the [correction-continue reviewer session][exit-session], line 22 runs
node tools/check.mjs followed by git status --short in one semicolon-separated
batch. Its result at line 25 contains a passing check message and batch exit
zero. Line 29 executes the same check separately, without an intervening source
edit. This is one additional check execution to obtain an attributable exit
status. The batch's final Git status cannot establish Node's exit code. The
retained offline control demonstrates the distinction on both failing and
passing source variants: a successful final Git command masks the failing
check's status, whereas the separate check reports 1 or 0 directly.

The reviewer in correction-continue was required to execute the check
independently; that obligation is necessary work. The extra same-reviewer
execution is the avoidable part. Likewise, a pre-fix failing check and a
post-fix check cover different states. By contrast, review-evidence-reuse
already demonstrates one post-edit implementation check, independent semantic
inspection by a distinct reviewer, and no reviewer or parent replay of the
passing check. These observations do not establish pervasive redundant testing
or justify removing independent review.

The existing 23,815-byte offline packet preserves 18 native observations and
six artifacts sufficient for its bounded stop/continuation claim. Its
711,164-byte source total spans three sessions; the 102,087-byte file read in
the live continuation spans one worker. Neither comparison measures actual
token savings, and the packet is not a substitute for a complete task review.
Incremental model input, reasoning turns and elapsed time attributable to these
operations have not been isolated. No aggregate savings percentage or fee
reduction follows from the operation counts or file sizes.

## Rule burden and evidence gaps

Current [Core][core] allows bounded direct work without tracking preflight and
does not require a worker, separate review or rerun for every phase transition.
In the [bounded-fix trajectory][bounded-sessions], six recorded tool calls include
one Implement Skill load, a failing pre-fix check and final verification; the
model did not create a Change or dispatch workers. The added before/at/after
expiry probe is not evidence of a blind rerun merely because the check also
appears before and after a source correction.

The maintainer interaction preceding this assessment repeatedly separated
small report boundaries into individual control, fix, review and commit cycles.
That is a local process observation, not a measured general property of RSP.
Core already supports compatible finding batches and evidence reuse. Changing
that usage pattern does not require another global workflow rule.

Rule length and repeated reading remain candidates for investigation, but
there is no matched rule-ablation experiment isolating their effect. Removing
independent review, cessation evidence or exact commit snapshots merely because
their tasks cost more would remove required protections without establishing
equivalent reliability.

Other gaps remain explicit: one full round does not establish repeated
stability; follow-ups with changed inputs are not matched efficiency comparisons;
provider/model portability is untested here; and the [11 calibration samples][labels]
remain candidate. Their AI assessment and original judge agreement do not supply
human ground truth or broad false-positive/false-negative rates.

### Minimal proposal, local priority and stopping boundary

The ordering below is local to the broader P3 rule-simplification question.
It identifies a bounded design candidate, not an approved rule correction.

1. **Local P1: clarify the two recovery-reference loading triggers.** Keep
   same-session worker pause/resume on the cessation, actual-effects,
   dispatch and result-attribution path. Load Capsule-specific format and
   persistent recovery instructions when a Capsule, durable snapshot or
   corresponding handoff format is actually needed. Preserve same-session
   authority, drift, evidence applicability and replay-safety checks; do not
   remove them merely because they currently share the Focus document. Stop
   when static reading-path review shows direct continuation can avoid
   Capsule-only content while genuine Capsule and cross-session recovery
   still reach all required safeguards. Do not expand a fixture matrix or
   claim future-model behavior from that static review.
2. **Local P2: apply the existing coordinator loading boundary.** Identify
   the parent's concrete need before preloading an executor method. No new
   blanket prohibition or anti-repetition prompt is needed. Stop when the
   load is justified by actual responsibility or omitted as unnecessary;
   retain full method access for a parent that performs relevant work and
   for each independently responsible worker.
3. **Local P3: defer generic cross-Skill deduplication.** Authority, stop
   conditions, independence, failure retention and exact Commit snapshots
   may need to be available at independently invoked entries. Extracting
   them into another shared document can add lookups rather than reduce
   burden. Without a concrete duplicate or misroute, stop without global
   prose extraction, word-count targets or a loading registry.

The smallest possible follow-up is a design clarification at the two
reference triggers, not a Core rewrite. Benefits remain unquantified and
changed model behavior untested. This assessment changes no rule and
authorizes no execution or adoption; all existing guidance candidates remain
isolated. The [loading audit and independent review evidence][loading-audit]
retain this inspection's source locations and limits. No report exception
boundary is part of the proposal.
