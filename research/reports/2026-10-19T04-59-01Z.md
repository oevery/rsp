## Interpretation and next experiment

Current Implement already admits boundaries only for an explicit requirement or evidenced producer, consumer, transition and material consequence. It admits permanent tests by observable consequence, a distinct plausible regression, an evidence gap and maintenance cost. Current Review similarly distinguishes useful independent tests from forwarding, shared-constant and source-string restatement. These rules are present; blanket bans on tests, hashes or defensive logic would conflict with the preservation controls.

The current evidence supports retaining those Skill rules rather than adding a blanket ban or another mandatory gate. No failure here establishes an absent rule, an Implement loading omission or a failure to apply its admission criteria. The strongest observed problems were in the evaluator. Do not convert the six semantic passes into suite-wide acceptance: the noise no-op control was initially invalid, two deterministic paths short-circuited, and the updated matrix has not run live.

For a later upstream distillation or candidate, map each proposed instruction to the existing Implement/Review owner and one observed counterexample. A missing acceptance fact is a contract problem; an already-read applicable rule with wrong implementation is an execution problem; an expected-answer gate is an evaluator problem. Only the first two can justify a corresponding Skill experiment. Use a matched candidate run only after selecting a concrete delta and authorizing execution. A later complex integration case should preserve the original ownership ambiguity, real consumer path and explicit acceptance boundary. Dedicated comment-quality coverage should distinguish a causal explanation of late-ACK recovery from comments that merely repeat assignments; this matrix did not test that distinction separately.

This single observation per case cannot establish reliability, causal contribution or general code quality. The prompts provide unusually explicit business authority and small source trees; they do not measure discovery in the original complex repository. No dedicated comment-quality case or fresh upstream survey is included. Historical upstream practice is context, not a fresh validation of upstream versions.
