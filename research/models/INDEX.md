# Research models

Cross-source models are added only when two or more completed source distillations support a useful synthesis. They are maintainer research, not RSP product truth. Record every input in frontmatter as `<source>@<revision> -> <report-path>`; compare those revisions with upstream status before reuse.

- `rsp-engineering-domain-model.md` — the engineering journey and domain ownership baseline.
- `rsp-skill-system.md` — the frozen historical 3.0 Skill System target and promotion rationale; use current Specs and capability reconciliation for present product status.
- `rsp-capability-coverage.md` — the accepted exact-path capability ledger and current reconciliation of upstream-derived RSP owners.
- `rsp-shaping-capability.md` — the selected shaping, slicing, shallow-Group, and Change-profile contract.
- `rsp-implementation-capability.md` — the selected standalone implementation and fresh-verification contract.
- `skill-quality-and-governance.md` — the accepted Skill-quality baseline, implemented Q1/Q3 maintainer foundation, and evidence-triggered Q2/Q4/Q5 conditions.
- `upstream-acceptance-decision.md` — the completed revision-acceptance wave and its separate product-candidate dispositions.
