# Upstream Distillation: temporal-workflow-observability

## Source Position
- **Evidence:** Temporal's TypeScript SDK distinguishes a cancellation request, propagation through cancellation scopes, cancellable versus non-cancellable work, acknowledgement, cleanup, and final workflow outcome (`packages/workflow/src/cancellation-scope.ts`, `packages/workflow/src/workflow.ts`).
- **Evidence:** Focused workflow tests distinguish signal receipt from handler execution/completion, preserve ordering, observe unfinished handlers, and coordinate cancellation while external activity remains live (`packages/test/src/workflows/signals-are-always-processed.ts`, `signal-update-ordering.ts`, `unblock-or-cancel.ts`, `handle-external-workflow-cancellation-while-activity-running.ts`).
- **Inference:** The reusable value is observer-authored event truth for evaluation and cancellation boundaries, not Temporal's durable workflow model.

## Extracted Mechanisms
- **M1 — Request, admission, handling, and completion are distinct facts.** Receiving a signal or cancellation request does not prove its handler or cleanup completed.
- **M2 — Cancellation is cooperative and scoped.** Work may be cancellable, shielded for cleanup, or still waiting on external settlement.
- **M3 — Observer history and worker return are different evidence channels.** Runtime events establish ordering and liveness independently from task-authored output.
- **M4 — Unfinished handlers remain visible.** Terminal progress must account for work still owned by an active handler.

## Applicable to RSP
- Managed-controller evaluation should derive worker lifecycle counts and ordering from host events when available, not an agent-authored evaluation receipt.
- Agent-reported routing, trigger, and correction semantics remain claims; unavailable host observations remain null with explicit omissions.
- Cancellation retains affected ResourceLeases until acknowledged settlement and owned background work release.

## Rejected
- Durable event history, workflow replay, task queues, cancellation scopes, deterministic runtime restrictions, and external workflow handles as RSP product concepts.
- Treating an evaluator event log as project truth or persisting it under `.rsp/`.
- Inferring success from the absence of a failure event.


## Recommendations
- **R1 — Make worker lifecycle metrics observer-authored (`independent-reimplementation`).** Parse host event names and order where exposed; otherwise record omissions.
- **R2 — Label producer semantic claims separately (`model-only`).** Agent self-report may explain routing but cannot prove dispatch, settlement, or release.
- **R3 — Preserve cooperative cancellation and cleanup boundaries (`model-only`).** Cancellation request never releases resources by itself.
- **R4 — Reject durable workflow history (`reject`).** Use event evidence only inside the evaluation or current host session.
