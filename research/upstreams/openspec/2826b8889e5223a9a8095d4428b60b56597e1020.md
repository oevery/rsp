# Upstream Distillation: openspec

- **Inference:** The update strengthens projection and configuration behavior but does not justify importing OpenSpec's artifact graph or lifecycle into RSP.

## Extracted Mechanisms

- **M1 — Operation guidance is injected by operation and schema rather than copied into every artifact.
- **M2 — Tool projection may select native Skills instead of generated commands, so host surfaces are policy rather than source truth.
- **M3 — Store and schema-root resolution are explicit and fail when ownership is ambiguous.
- **M4 — Update rereads dependencies before regeneration, preventing stale derived artifacts.

## Applicable to RSP

- Re-read authoritative owners before regenerating host projections or derived indexes.
- Keep host command/Skill projection separate from canonical RSP artifacts.
- Fail closed on ambiguous schema or store ownership.

## Rejected

- Adding stores, artifact graphs, schema-selected workflows, or apply/archive command parity to RSP.
- Treating generated host commands as current product truth.
- Adopting pending OpenSpec Changes as stable mechanisms.

## Recommendations

- **R1 — Retain source-versus-projection separation (model-only).**
- **R2 — Add authoritative reread before deterministic regeneration where RSP owns projections (model-only).**
- **R3 — Keep OpenSpec lifecycle and store model external (reject).**
