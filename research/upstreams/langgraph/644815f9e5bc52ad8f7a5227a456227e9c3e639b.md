# Upstream Distillation: langgraph

## Source Position
- **Evidence:** LangGraph persists execution by thread/checkpoint namespace, resumes interrupts through commands, and replays node work around interruption boundaries (`libs/langgraph/langgraph/types.py`, `libs/langgraph/langgraph/_internal/_replay.py`, `libs/langgraph/tests/test_interruption.py`).
- **Evidence:** Subgraph persistence tests distinguish fresh per-call state from checkpointed state shared through a thread, while Pregel tests cover concurrent updates and deterministic reducers (`libs/langgraph/tests/test_subgraph_persistence.py`, `libs/langgraph/tests/test_pregel.py`).
- **Inference:** RSP needs a distinction between a reusable worker context and one admitted execution call, but not LangGraph's checkpoint store or graph runtime.

## Extracted Mechanisms
- **M1 — Context lifetime and invocation lifetime differ.** A thread can retain state across calls while each invocation still has its own inputs, interruption, result, and replay boundary.
- **M2 — Replay safety belongs to the executed unit.** Resume can replay code around an interrupt, so side effects before the checkpoint require idempotence or inspection (`libs/langgraph/tests/test_interruption.py`).
- **M3 — Shared state constrains concurrency.** Concurrent writers require explicit combination semantics; a stateful context cannot be assumed safe for overlapping calls (`libs/langgraph/tests/test_pregel.py`).
- **M4 — Namespace identity is not business ownership.** Checkpoint namespaces locate execution state but do not define the graph's product intent or acceptance.

## Applicable to RSP
- Split `WorkerSession`, the reusable context/identity container, from `WorkerInvocation`, exactly one Assignment or AssignmentDelta from admission through settlement and release.
- Permit at most one context-mutating active WorkerInvocation per stateful WorkerSession; parallel work requires separately evidenced execution contexts.
- Attach resume safety and cancellation ownership to each WorkerInvocation rather than the entire reusable session.
- Continue rejecting durable checkpoint or execution graphs under `.rsp/`.

## Rejected
- Graph nodes, Pregel channels, reducers, checkpoint stores, namespaces, replay engines, and durable thread state as RSP workflow entities.
- Assuming one WorkerSession handle proves parallel isolation.
- Replaying a non-repeatable Assignment because the host can technically resume a thread.


## Recommendations
- **R1 — Add transient `WorkerInvocation` identity (`model-only`).** Each admitted call owns cancellation, settlement, Receipt, and release observations.
- **R2 — Restrict overlapping stateful invocations (`independent-reimplementation`).** One stateful WorkerSession has at most one active context-mutating invocation unless the host proves distinct namespaces and resources.
- **R3 — Keep replay safety invocation-scoped (`model-only`).** Resume follows the current Assignment's `idempotent | inspect-before-repeat | non-repeatable` contract.
- **R4 — Reject checkpoint persistence (`reject`).** Recovery continues from repository evidence and fresh host observations.
