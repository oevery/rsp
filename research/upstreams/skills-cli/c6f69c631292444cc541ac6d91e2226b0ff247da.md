# Upstream Distillation: skills-cli

## Source Position

- **Evidence:** The installer/update CLI expands private-repository security, Git transport allowlists, blob/tree acquisition, source updates, local/Skill locks, discovery, removal, telemetry, and hostile-input tests (src/**, tests/private-repo-add-security.test.ts, tests/git-transport-allowlist.test.ts).
- **Inference:** Remote Skill ingestion has become more mature, but RSP still has no demonstrated need to embed a general network installer.

## Extracted Mechanisms

- **M1 — Transport and source trust are explicit:** Git/HTTP acquisition is allowlisted and private-source authentication is tested.
- **M2 — Content acquisition and installation state are separate:** blobs/trees, source identity, local lock, and Skill lock have distinct owners.
- **M3 — Update/removal preserve managed ownership:** the tool distinguishes managed files and source refresh from arbitrary user content.
- **M4 — Security tests target remote/private edge cases rather than only happy-path installation.

## Applicable to RSP

- If remote ingestion is ever selected, require immutable source identity, transport allowlists, credential-safe errors, path containment, and managed ownership records.
- Keep installation locks outside RSP Change/Spec lifecycle state.
- Treat new upstream Skills as notice-only until exact user selection.

## Rejected

- Adding remote installation/update merely for ecosystem parity.
- Copying network, archive, lock, or telemetry code without a selected RSP product need.
- Sending credentials or private repository identifiers into logs or research reports.

## License and Reuse

- Root LICENSE and package.json declare MIT.
- Model-only now; a future selected remote-ingestion Change must cite exact source paths, revision, and MIT notice before reuse.

## Recommendations

- **R1 — Keep the RSP package installer closed to arbitrary remote sources (model-only).**
- **R2 — Preserve a remote-ingestion security checklist as capability inventory (model-only).**
- **R3 — If selected later, independently implement the smallest source adapter with hostile-input tests (independent-reimplementation).**
