## Extracted Mechanisms

### M1 — Ordered reuse decisions

The main Skill inspects the problem and affected flow before choosing existing
code, standard facilities or a minimal new implementation. It explicitly retains
trust-boundary validation, data-loss protection, security and accessibility.
The five auxiliary entrypoints deliver different outcomes rather than repeat
that entire implementation method.

Local inference: arrange guidance around the decision the task actually needs;
merge competing explanations of that decision before adding another restriction.
This does not justify a fixed sequence of RSP capabilities or blind deletion.

### M2 — Concrete findings and bounded exceptions

Review and Audit add an explicit reuse category and numbered findings; Review
illustrates location, unnecessary work and a replacement. Audit adds a search
for references, including tests and dynamic/string uses, before a deletion finding.
Debt now includes block-comment markers and excludes common dependency/build
directories in its example scan. Its output distinguishes a simplification
with a known reconsideration trigger from one without such a trigger.

Local inference: short examples can replace repetitive output explanations, while
real limits belong beside the action or in its selected branch. Repository-wide
search and marker syntax remain upstream methods, not general RSP requirements.

### M3 — Historical benefit is not local acceptance

Gain now uses the agentic benchmark averages instead of older single-shot medians.
Its source, `benchmarks/results/2026-06-18-agentic.md`, describes Haiku 4.5, twelve
feature tasks with four runs each and a separate safety tier. It reports reductions
of 22% in tokens and 20% in cost on the feature tier. Those are upstream historical
claims, not measurements made here. The report states that feature runs did not
exercise a server/browser, limits safety conclusions, and discloses incomplete
cost/time observations for four feature cells.

The current delta also changes `benchmarks/agentic/run.py` to retain the configured
plugin override and exclude ambient project instructions/auto-memory from cells.
`benchmarks/correctness.js` improves failure reporting, stops swallowing a CSV
exception and explicitly labels two checks as structural rather than runtime
verification. These fixes do not retroactively validate earlier benchmark results;
this pass supplies no rerun or causal attribution for those historical numbers.

### M4 — Portable prose and host state are different surfaces

The hook delta adds host-specific output/activation handling, project-keyed mode
state with a shared fallback, bounded regex execution and stdin settlement changes.
`hooks/ponytail-mode-tracker.js` removes Review's persistent mode transition.
README moves detailed install instructions to another document and clarifies
command targeting. These are source observations, not tested host compatibility.
The main Skill still carries persistent mode, rigid output and concrete hardware/
test prescriptions; the upstream is not a uniformly minimal rule set.
