# Upstream Distillation: anthropic-skill-creator

## Source Position

- **Evidence:** `skills/skill-creator/` is a self-contained Skill authoring and optimization toolkit with one `SKILL.md`, grader/analyzer/comparator agents, schemas, validation, eval execution, benchmark aggregation, description optimization, packaging, and a review viewer.
- **Inference:** It is a focused reference for the maintainer promotion gate, not a user-facing RSP workflow dependency.

## Extracted Mechanisms

- **M1 — Progressive Skill artifact:** metadata stays always visible, the body loads on trigger, and resources/scripts support deeper work (`skills/skill-creator/SKILL.md`).
- **M2 — With/without comparison:** eval runs compare candidate behavior with a baseline and grade explicit expectations; aggregate output includes pass rate, time, tokens, variance, and deltas (`agents/grader.md`, `scripts/aggregate_benchmark.py`, `references/schemas.md`).
- **M3 — Holdout description optimization:** should-trigger and hard should-not-trigger prompts are split into stratified train/test sets; candidate descriptions are selected by held-out score rather than training score (`scripts/run_loop.py`, `scripts/run_eval.py`, `scripts/improve_description.py`).
- **M4 — Human-readable review remains first class:** structured grades and aggregate metrics are paired with rendered outputs and analyst notes so non-discriminating assertions and high variance remain visible (`eval-viewer/**`, `agents/analyzer.md`).

## Capability Inventory

| Skill path | Trigger and output | Boundary | RSP disposition |
| --- | --- | --- | --- |
| `skills/skill-creator/SKILL.md` | Create, modify, evaluate, benchmark, package, or optimize a Skill | Writes only the explicitly selected Skill/eval workspace; model calls and browser viewer are optional host operations | `adapted` only for selected maintainer evaluation mechanisms |

## Applicable to RSP

- Use a stable eval schema with prompt, expected output, verifiable expectations, grading evidence, and aggregate cost/variance.
- Require a small unseen holdout when optimizing descriptions or instruction wording.
- Compare candidate Skills against the current published behavior instead of relying on one-sided success.
- Keep qualitative artifact review beside quantitative metrics.

## Rejected

- Automatically rewriting a published RSP Skill from benchmark output.
- Treating a provider-specific trigger runner as portable proof across hosts.
- Making user feedback, browser viewers, or repeated model calls mandatory for every small edit.
- Optimizing descriptions against easy or obviously irrelevant negatives.

## License and Reuse

- `skills/skill-creator/LICENSE.txt` is Apache-2.0; the repository root has no blanket license for unrelated directories.
- Adaptation must stay within `skills/skill-creator/**`, preserve the Apache-2.0 notice, document modifications, and retain the reviewed revision.
- RSP should independently implement its portable schemas and gates unless exact scripts are deliberately selected by a future Change.

## Recommendations

- **R1 — Standardize Skill eval receipts (`independent-reimplementation`).** Record expectations, evidence, pass/fail, cost, elapsed time, tool calls, and variance in a host-neutral schema.
- **R2 — Add a holdout gate for description changes (`adapt`).** Use difficult positive and near-miss negative prompts and choose by unseen performance.
- **R3 — Preserve qualitative review beside metrics (`model-only`).** Flag non-discriminating assertions, high variance, and artifact-quality concerns.
- **R4 — Keep automated rewriting outside publication authority (`model-only`).** Suggested edits remain candidate input to a normal RSP Change.
