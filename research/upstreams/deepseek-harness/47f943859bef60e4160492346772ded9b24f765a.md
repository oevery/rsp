# Upstream Distillation: deepseek-harness

## Source Position

- **Evidence:** DeepSeek Harness is a plugin-composed agent harness whose repository-local `.agents/` surface contains 11 operational Skills and more than two thousand Agent Note files, while `scripts/**` mechanically enforces repository, documentation, and release invariants (`AGENTS.md`, `.agents/**`, `scripts/**`).
- **Inference:** RSP already has the stronger portable work-state and authority model; this source is useful for repository-specific Skill assembly, durable note governance, and executable documentation gates.

## Extracted Mechanisms

- **M1 — Repository Skills are narrow adapters:** every `dsh-*` Skill binds a concrete repository policy, tool surface, and stop condition instead of restating a generic engineering lifecycle (`.agents/skills/**`).
- **M2 — Agent Notes preserve future decision value:** non-trivial changes require a note, implemented notes are classified and archived, rejected notes survive only while they prevent a tempting mistake, and archived notes are frozen (`AGENTS.md`, `.agents/skills/dsh-archive-agent-notes/SKILL.md`, `.agents/notes/README.md`).
- **M3 — Gates select evidence by changed surface:** pre-push checks choose the smallest relevant checks and distinguish local focused evidence from CI-owned exhaustive matrices (`.agents/skills/dsh-pre-push-checks/SKILL.md`, `scripts/run-gates.ts`).
- **M4 — Prose is treated as executable surface:** documentation budgets, current-state prose, reasoning-leak cleanup, bilingual projection, and site mapping are enforced through dedicated Skills and scripts (`dsh-doc-standards`, `dsh-prose-standard`, `dsh-trim-cot-leakage`, `dsh-doc-site-sync`).

## Applicable to RSP

- Keep RSP Skills portable and let projects add narrow repository adapters rather than expanding the core suite for every policy.
- Add documentation/prose checks only when they are mechanically executable and owned by a project or publication surface.
- Use change-surface evidence selection without treating a clean working tree, push readiness, or CI as implementation authority.
- Retain research or rationale only when it has future decision value; freeze archived evidence.

## Rejected

- Importing the harness plugin architecture, full Agent Note corpus, or repository-specific GitHub stack workflow.
- Requiring every non-trivial RSP Change to create a parallel Agent Note.
- Treating `clean`, pre-push checks, GIF publication, or bilingual synchronization as universal completion gates.
- Copying project prose standards into portable Skills.

## Recommendations

- **R1 — Document the project-adapter seam (`model-only`).** Core RSP Skills own portable contracts; repository Skills own local gates and host tools.
- **R2 — Add decision-value retention to research maintenance (`independent-reimplementation`).** Archive or remove superseded research without preserving chronology as current authority.
- **R3 — Evaluate changed-surface check selection (`model-only`).** Keep Required evidence exact while leaving exhaustive platform coverage to CI or an explicit release candidate.
- **R4 — Keep clean-tree and publication gates external (`reject`).** They may be project checks but cannot become universal RSP authority.
