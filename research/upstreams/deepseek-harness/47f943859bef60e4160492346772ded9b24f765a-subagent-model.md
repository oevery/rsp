# Upstream Distillation Supplement: DeepSeek Harness Subagent Model

## Source Position

- **Evidence:** DeepSeek Harness models a continuable child as one durable Session plus at most one process-local Activation. The Agent inbox remains the only FIFO; the continuation manager derives residency from Agent quiescence and owned children instead of adding a second request state machine (`.agents/notes/implemented/feature/2026-07-28-continuable-subagent-conversations.md`).
- **Evidence:** Parent-to-child delivery, child-authored reports, current-turn interrupt, and manager-authored settlement are separate operations with distinct authority and postconditions. Message source records attribution but does not grant authority; caller cancellation controls work only until inbox acceptance (`.agents/notes/implemented/feature/2026-07-28-continuable-subagent-conversations.md`, `.agents/notes/implemented/feature/2026-07-30-continuable-subagent-report-tool.md`, `.agents/notes/implemented/feature/2026-08-06-continuable-subagent-interrupt.md`, `.agents/notes/implemented/feature/2026-08-06-manager-owned-subagent-settlement-delivery.md`).
- **Inference:** DeepSeek Harness is useful here as a runtime-boundary reference, not as a runtime to reproduce. RSP already owns durable work through Change, Group, Spec, and archive artifacts and intentionally keeps WorkerSessions, Assignments, Receipts, leases, topology, and recovery chronology transient.

## Extracted Mechanisms

- **M1 — One outer lifecycle is derived from owned facts.** `running`, `waiting`, and `settled` are derived from Agent quiescence, accepted inbox work, and the owned-child set. The child manager does not add a peer queue or another result-bearing Task (`.agents/notes/implemented/feature/2026-07-28-continuable-subagent-conversations.md`).
- **M2 — Admission transfers cancellation ownership.** Before inbox acceptance, the caller signal may cancel lookup, materialization, or admission and the child is rolled back without ids. After acceptance returns a stable message id, caller cancellation cannot retract the accepted turn; stopping it requires the separate current-turn interrupt contract (`.agents/notes/implemented/feature/2026-07-28-continuable-subagent-conversations.md`, `.agents/notes/implemented/feature/2026-08-06-continuable-subagent-interrupt.md`).
- **M3 — Attribution never grants authority.** Direct-parent delivery is authorized by an exact live parent and durable direct-parent lineage. `MessageSource` and `senderSessionId` record provenance only. Interrupt is deliberately broader because it is idempotent and delivers no content, but still requires an exact durable parent address or exact live ancestor identity (`.agents/notes/implemented/feature/2026-07-28-continuable-subagent-conversations.md`, `.agents/notes/implemented/feature/2026-08-06-continuable-subagent-interrupt.md`).
- **M4 — Authored report and observed settlement are different evidence.** A child may report zero or many times without ending its turn. Independently, the manager sends one unconditional settlement account for every announced Activation, including cancellation, refusal, token exhaustion, and failure. Manager-authored settlement uses a different source kind and cannot be attributed to the child (`.agents/notes/implemented/feature/2026-07-30-continuable-subagent-report-tool.md`, `.agents/notes/implemented/feature/2026-08-06-manager-owned-subagent-settlement-delivery.md`).
- **M5 — Settlement precedes ownership release.** The manager attempts settlement delivery while the parent still owns the child, so the parent cannot settle in the delivery window. Delivery failure is logged but never pins teardown; the child Session remains the durable record and no mailbox, retry ledger, or exactly-once claim is invented (`.agents/notes/implemented/feature/2026-08-06-manager-owned-subagent-settlement-delivery.md`).
- **M6 — Capability requests fail loud.** Provider start-time capabilities are explicit and checked before delegation; unsupported structured output, depth, tool filtering, or persona requests reject instead of being silently ignored. Continuable creation is discovered through method presence so a flag cannot drift from the implementation (`.agents/notes/implemented/feature/2026-06-21-subagent-capability-seam.md`).
- **M7 — Delegation snapshots effective policy once.** The continuable child captures its delegation policy before the first await and persists it in the child log. Cold resume replays that snapshot instead of inheriting the parent's current policy (`.agents/notes/implemented/feature/2026-08-10-continuable-subagent-policy-inheritance.md`).
- **M8 — Terminal output and terminal reason are orthogonal.** A non-completed run may retain partial output; an empty usage-only terminal message does not erase an earlier non-empty assistant message. Consumers share one selection rule while the stop reason still prevents partial output from being reported as success (`.agents/notes/implemented/bug-fix/2026-08-10-subagent-empty-terminal-message-output.md`).

## Applicable to RSP

- Preserve `ControlOutcome` as the only user-visible status flow and keep worker/runtime details nested. DeepSeek's derived Activation conditions are supporting evidence for the current RSP simplification, not a request for more statuses.
- Treat an Assignment's host-observed admission as an ownership-transfer boundary: before admission the controller may abandon the dispatch; after admission it must use an explicit host cancellation or interrupt operation and retain affected ResourceLeases until real acknowledgement or settlement.
- State explicitly that WorkerSession identity, message source, and sender provenance establish continuity or attribution only. They do not grant mutation, lifecycle, Git, publication, approval, or broader Assignment authority.
- Keep worker-authored Receipt content separate from controller-observed settlement. Settlement proves that the runtime obligation stopped; only a schema-valid Receipt plus inspected evidence can prove the lane result. Partial output may guide recovery but cannot synthesize success.
- Add deterministic model fixtures for admission-before-cancel, settlement-without-Receipt, live owned background work, empty terminal output, and non-completed partial output. These are contract tests, not runtime implementation requirements.

## Rejected

- A durable RSP worker Session catalog, Activation registry, inbox, mailbox, delivery receipt, retry log, process lease graph, or conversation tree.
- Persisting WorkerSession ids, Assignment ids, raw Receipts, sender ids, runtime ancestry, or settlement notices in `.rsp/focus.d/`; the Focus Capsule remains a bounded current/evidence/next pointer.
- Treating child-authored prose, final assistant output, heartbeat, or manager settlement as a valid managed Receipt.
- Reconstructing authority from worker lineage, message provenance, current parent context, or a resumed worker's ambient sandbox.
- Copying DeepSeek's provider registry, capability descriptor, durable Session schema, depth policy, report tool, or interrupt RPC into portable RSP Skills.
- Declaring every sibling delegation concurrency-safe. DeepSeek explicitly accepts shared-workspace races; RSP must continue deriving parallelism from exact writer seams and ResourceLeases.

## Recommendations

- **R1 — Define Assignment admission as the cancellation ownership boundary (`model-only`).** Add one concise invariant to `rsp-manage`: failed or cancelled creation before host-confirmed admission creates no dispatch; after admission, caller abandonment does not retract work, and only an explicit host interrupt/cancel plus acknowledgement may release its leases. Do not require a new id, status, or persisted record.
- **R2 — Separate runtime settlement from Receipt acceptance (`independent-reimplementation`).** State that controller-observed completion, cancellation, or worker disappearance may close liveness and resource accounting but cannot manufacture a lane result. A missing schema-valid Receipt keeps acceptance `incomplete`; partial output is recovery evidence only.
- **R3 — Make provenance non-authoritative explicit (`model-only`).** Clarify that WorkerSession identity and message provenance support same-session continuity and attribution only; effective authority still comes exclusively from the current Assignment or eligible AssignmentDelta envelope.
- **R4 — Add five unseen boundary fixtures (`independent-reimplementation`).** Cover pre-admission cancellation, post-admission caller cancellation, settlement without Receipt, outstanding owned background work, and partial/empty terminal output. Assert outer `ControlOutcome`, acceptance, lease release, and recovery behavior without asserting a host-specific runtime implementation.
- **R5 — Retain the current non-runtime architecture (`reject`).** Do not adopt durable child Sessions, Activation state, provider registries, inboxes, settlement mailboxes, or Focus Capsule runtime data.
