## Source Position

- **Evidence:** This revision makes two normative clarifications in docs/specification.mdx: metadata is a string-to-string map, and files/directories beyond SKILL.md are permitted while scripts/references/assets remain conventions rather than an exhaustive schema.
- **Inference:** RSP's progressive resource layout remains conformant, but validators must reject non-string metadata values without forbidding additional self-contained resources.

## Extracted Mechanisms

- **M1 — Typed extension metadata:** metadata keys and values are strings, preserving portable serialization and preventing host-specific nested structures.
- **M2 — Open resource envelope:** a Skill directory may contain arbitrary additional resources; named optional directories are organization recommendations.

## Applicable to RSP

- Keep metadata validation string-to-string.
- Validate path containment, packaging, licensing, and references without restricting resource directory names to a closed list.
- Preserve RSP's stronger self-containment and standalone-install checks as product policy above minimum conformance.

- Adding nested metadata objects for RSP-only state.
- Removing RSP packaging checks merely because the specification permits extra files.

- **R2 — Keep the resource envelope open but contained (conform).** Unknown directories are allowed when packaged paths remain inside the Skill and pass security checks.
