# Upstream Distillation: skillspector

## Source Position

- **Evidence:** SkillSpector is a pre-install Skill scanner combining deterministic static analyzers, optional semantic model analysis, MCP permission/tool-poisoning checks, dependency vulnerability lookup, risk scoring, baseline suppression, and terminal/JSON/Markdown/SARIF output (README.md, src/**, docs/**).
- **Inference:** It supplies a missing Skill supply-chain security model, but integration must expose network/data-egress choices and false-positive handling.

## Extracted Mechanisms

- **M1 — Inventory before interpretation:** independent analyzers cover prompt injection, data exfiltration, unsafe execution, secrets, dependencies, MCP behavior, and least privilege (src/skillspector/nodes/**).
- **M2 — Deterministic and semantic layers are separable:** --no-llm retains local static analysis; semantic analysis sends eligible file contents to the configured provider (README.md, src/skillspector/**).
- **M3 — Incremental CI uses exact suppression:** versioned baselines combine reviewed glob rules with content/version fingerprints so old findings can be suppressed without hiding changed content (docs/SUPPRESSION.md, src/skillspector/suppression.py).
- **M4 — Machine-readable policy:** exit codes, risk levels, JSON, and SARIF support deterministic installation or CI gates (README.md, src/skillspector/reporting/**).
- **M5 — Network behavior is explicit:** optional LLM analysis can send file contents; OSV lookup sends dependency coordinates and falls back to a bundled list offline (README.md, docs/SC4-osv-live-vulnerability-lookups.md).

## Applicable to RSP

- Add a pre-promotion security inventory for executable scripts, undeclared permissions, prompt injection, secret access, network sinks, and MCP/tool metadata drift.
- Keep a fully local deterministic mode and treat semantic/provider analysis as optional evidence.
- Use reviewed exact-fingerprint suppression so a baseline cannot silently suppress changed content.
- Emit machine-readable findings suitable for CI without making the scanner a runtime dependency.

## Rejected

- Claiming static analysis proves runtime safety or sandboxing.
- Sending Skill contents or dependency coordinates over the network without explicit configuration and disclosure.
- Copying the full LangGraph implementation into RSP.
- Auto-installing a Skill solely because the scanner reports a low score.

## Recommendations

- **R1 — Define a Skill supply-chain security gate (independent-reimplementation).** Start with deterministic checks for scripts, permissions, secrets, egress, prompt injection, and MCP metadata.
- **R2 — Add content-bound suppression (model-only).** Reviewed findings remain suppressed only while exact relevant content and rule identity remain stable.
- **R3 — Keep semantic scanning optional and disclosed (model-only).** Record provider, transmitted scope, network use, and omissions in the verification receipt.
- **R4 — Evaluate external SkillSpector integration before reuse (tooling).** Compare coverage, false positives, offline behavior, and maintenance cost.
