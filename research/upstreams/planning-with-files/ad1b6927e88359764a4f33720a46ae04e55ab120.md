# Upstream Distillation: planning-with-files

## Source Position

- **Evidence:** planning-with-files is an opt-in disk-backed planning and recovery system with host hooks, adapters, plan directories, and session state. This revision hardens multi-root and multi-session resolution after failures caused by shared parent working directories (`.agents/skills/planning-with-files/SKILL.md`, `scripts/inject-plan.sh`, `scripts/resolve-plan-dir.sh`, `scripts/session-catchup.py`).
- **Evidence:** The new behavior adds an explicit `PWF_PLAN_ROOT` root pin, session attachment checks, nested-plan ambiguity refusal, root-scoped recovery filtering, and tests covering two sessions sharing one parent cwd (`scripts/inject-plan.sh`, `scripts/resolve-plan-dir.sh`, `tests/test_catchup_cross_project_guard.py`, `tests/test_resolver_plan_root_pin.py`, `tests/test_codex_nested_root_isolation.py`).
- **Inference:** The revision is strong evidence about ambient recovery hazards. It is not evidence that RSP should adopt its `.planning` files, hooks, mtime selection, or controller ledger.

## Extracted Mechanisms

### M1 — Explicit project binding must outrank the working directory

- **Evidence:** `PWF_PLAN_ROOT` selects the effective planning root, overrides cwd-derived resolution, and a broken pin returns no plan rather than falling back to the shared parent (`scripts/resolve-plan-dir.sh`, `scripts/inject-plan.sh`, `tests/test_resolver_plan_root_pin.py`).
- **Inference:** A recovery handle inferred from process cwd is unsafe when multiple projects can be nested below or share the same parent. An explicit project/work owner is stronger than convenience discovery.

### M2 — Ambiguity must refuse rather than choose a plausible plan

- **Evidence:** When a cwd-derived plan competes with a live nested plan, injection refuses to select either. The tests assert that two independently pinned threads see only their own plans and that an unpinned thread beside them receives an ambiguity result (`scripts/inject-plan.sh`, `tests/test_codex_nested_root_isolation.py`).
- **Inference:** Selection safety is a correctness boundary: the safe fallback for competing operational state is “no controller context,” not newest, nearest, or parent state.

### M3 — Session attachment prevents ambient state inheritance

- **Evidence:** A `.planning/sessions` directory arms a session identity check; an unattached session does not receive plan context, and the source distinguishes diagnosable user-prompt notices from silent high-frequency hook paths (`scripts/inject-plan.sh`, `tests/test_codex_nested_root_isolation.py`).
- **Inference:** Any automatic host projection must be opt-in per session and remain inert for unrelated or one-shot work. Operational state must not silently cross thread boundaries merely because cwd is shared.

### M4 — Every dependent operation must use the selected identity

- **Evidence:** The revision fixes ledger summaries, cache keys, and catch-up lookup so they resolve from the selected root and recorded cwd rather than the caller's current directory (`scripts/inject-plan.sh`, `scripts/session-catchup.py`, `tests/test_catchup_cross_project_guard.py`, `tests/test_resolver_plan_root_pin.py`).
- **Inference:** Selecting a controller run once is insufficient if later reads, caches, and summaries re-resolve through ambient cwd. Identity propagation is an end-to-end invariant.

## Applicable to RSP

- RSP currently selects its work through explicit `focus.d/` markers and resolves one focused Change, rather than injecting a plan selected by cwd. Its continuation contract also requires reopening owners and checking drift before resuming (`skills/rsp/SKILL.md`, `src/commands/show.ts`).
- This means M1 and M2 reinforce existing RSP choices: a focused WorkRef is authoritative, and no focus or conflicting focus must stop rather than guess. They do not justify an additional run pointer or plan-discovery fallback.
- The concrete future gap is bounded to host-projected managed recovery. If RSP ever adds ambient per-thread controller state, it must bind it to an explicit repository root and WorkRef, reject ambiguity and path escape, propagate that identity to every cache/summary/recovery operation, and remain absent by default.

## Rejected

- **The `.planning` three-file model and append-only ledger as RSP core state:** they duplicate the focused Change, its Tasks, Verify evidence, and Blockers, creating a second current-work authority.
- **Cwd, newest-by-mtime, or root-file fallback to select an RSP Change:** these are intentionally weaker than `focus.d/` and would make recovery non-deterministic.
- **Always-on hook injection:** RSP has no demonstrated need for ambient context injection; it adds token cost, host drift, and cross-thread leakage risk.
- **Persisting session identities under `.rsp/`:** session attachment is host-operational state, not durable product or lifecycle truth.
- **Direct adoption of this repository's scripts or adapters:** the useful result is its tested safety constraints, not its hook implementation or directory structure.


## Recommendations

- **R1 — Preserve explicit WorkRef selection and fail-closed recovery (`model-only`).** Keep `focus.d/` and selected-owner validation as the only ordinary work selectors; never add cwd or timestamp fallback.
- **R2 — Gate any future host-managed recovery behind an isolated-run design (`independent-reimplementation`).** A selected run must carry one explicit project root and WorkRef through every recovery, cache, summary, and worker handoff; no identity may be recomputed from cwd.
- **R3 — Add multi-root isolation holdouts only when such a host projection is proposed (`model-only`).** Test two projects below one parent cwd, one pinned and one unpinned session, invalid pins, nested competing state, stale state, and cache/summary leakage. Until then, this is a future design constraint, not a Core change.
- **R4 — Keep no-controller/no-effect as the default (`model-only`).** Any optional controller path needs explicit per-session attachment and a diagnosable refusal mode; it may not change unrelated agent sessions.
