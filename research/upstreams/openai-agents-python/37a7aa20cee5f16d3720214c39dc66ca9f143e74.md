# Upstream Distillation: openai-agents-python

## Source Position
- **Evidence:** The SDK exposes handoffs as a transfer to another agent, while `Agent.as_tool()` invokes a specialist without transferring the orchestrator's control. Both surfaces support typed inputs, and agent tools can expose structured outputs or an explicit output extractor (`docs/handoffs.md`, `docs/tools.md`).
- **Evidence:** `RunResult` and `RunState` separately represent final outputs, generated items, last active agent, interruptions, approvals, and resumable run state (`docs/results.md`, `src/agents/run_state.py`).
- **Inference:** The useful RSP mechanism is the distinction between phase-control transfer and bounded work delegation, not the SDK's agent graph or session implementation.

## Extracted Mechanisms
- **M1 — Transfer and invocation are distinct relationships.** Handoffs change the active agent; agent tools retain the caller as orchestrator (`docs/handoffs.md`, `docs/tools.md`).
- **M2 — Delegation contracts can be typed on both sides.** Tool-agent parameters are locally schema-validated and structured output can be returned without reconstructing it from prose (`docs/tools.md`).
- **M3 — Runtime continuation is not final acceptance.** `RunState` can serialize interrupted execution while `RunResult` owns final output and generated evidence (`docs/results.md`, `src/agents/run_state.py`).
- **M4 — Context transfer is explicit.** A handoff may filter history; an agent tool constructs a nested input instead of implicitly inheriting the complete conversation (`docs/handoffs.md`, `docs/tools.md`).

## Applicable to RSP
- Core-to-Manage and Core-to-Discipline are control transfers. Manage-to-worker is work delegation; a worker never becomes owner of the selected managed goal.
- Define a worker-authored structured `WorkerReceipt`, then keep Manager validation as a separate acceptance operation.
- Preserve Assignment references and bounded facts instead of forwarding the complete controller conversation.
- Keep resumable host run state outside `.rsp/`; RSP continues to rederive current authority and evidence on recovery.

## Rejected
- Importing the Agents SDK runner, session stores, agent graph, handoff history, approvals, provider models, or sandbox implementation.
- Treating a handoff tool call as the model for Manage-to-worker dispatch; RSP workers do not receive phase control.
- Treating schema-valid worker output as accepted evidence without Manager inspection.


## Recommendations
- **R1 — Separate `ControlTransfer` from work delegation (`model-only`).** Core transfers phase control; Manage retains control while issuing bounded Assignments.
- **R2 — Separate `WorkerReceipt` from accepted lane evidence (`independent-reimplementation`).** Require a structured claim, then validate it against actual paths, diff, verification, authority, and host observations.
- **R3 — Keep context transfer explicit and minimal (`model-only`).** Assignments carry exact references and bounded facts rather than implicit conversation inheritance.
- **R4 — Reject SDK runtime persistence as RSP state (`reject`).** RunState-like data remains host-native and transient.
