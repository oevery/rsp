# Upstream Distillation: gsd-core

## Source Position

- **Evidence:** This large revision extends GSD from a command workflow toward an explicit capability ecosystem with capability descriptors, command contributions, state writers, orchestration seams, provenance, skill-surface budgets, untrusted-input controls, prohibition enforcement, and context management (docs/adr/**, docs/explanation/**, agents/**, commands/**, src/**).
- **Inference:** It provides adversarial evidence for modular host orchestration and budgeted capability surfaces, but remains much broader and more stateful than RSP's minimum repository protocol.

## Extracted Mechanisms

- **M1 — Capability descriptors separate declaration from routing and state writing.** Extension contributions can be discovered without embedding every behavior in one controller.
- **M2 — Skill/agent surface budgets are ratcheted.** Prompt and capability growth is treated as a measurable maintenance risk.
- **M3 — Untrusted input and prohibitions are explicit evaluation seams.** Boundary claims are represented as enforceable checks rather than prose-only advice.
- **M4 — Resolution provenance and emitted-artifact attribution identify which capability produced durable output.

## Applicable to RSP

- Keep host capability discovery and execution adapters outside canonical RSP truth.
- Add measurable context/surface budgets to Skill promotion evidence.
- Record exact source capability and projection when host-generated artifacts are evaluated.
- Represent hard prohibitions as deterministic checks where possible.

## Rejected

- Importing the capability ecosystem, command hub, phase state writers, autonomous convergence, or runtime overlay.
- Expanding RSP's lifecycle/entity graph to mirror GSD.
- Treating budget compliance or command exit zero as task correctness.

## Recommendations

- **R1 — Add context/surface budget receipts to Skill promotion (model-only).** Measure loaded instructions and optional resources instead of enforcing prose word counts.
- **R2 — Preserve capability/projection provenance in host evals (model-only).**
- **R3 — Keep runtime capability orchestration external (reject).** RSP artifacts remain the only durable work owner.
