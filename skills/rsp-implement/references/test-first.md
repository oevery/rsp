# Risk-selected test-first implementation

Load only after a clear authorized behavior and owning production/test seam are known, when test-first is explicitly required or a concrete changed risk makes pre-mutation RED materially safer. An unexplained symptom goes to diagnosis first. Require test and product mutation authority and an executable focused check. A test cannot create product authority, a public compatibility path, or an unreachable state.

Identify the observable consequence, one distinct plausible regression, gap in current checks and maintenance cost. Add the smallest test at the real consumer seam. Run it before production mutation and observe the expected behavioral RED. Syntax, fixture, environment or unrelated baseline failures are not RED. If it passes, improve the discriminating check or stop. Make the smallest GREEN change and rerun the same check. Refactor only for a concrete improvement while green; do not widen interfaces or add test-only hooks to force GREEN.

Retain a permanent test only when it protects observable behavior or a real boundary with distinct future value and proportionate cost, unless user/Change/project authority requires retention. Otherwise remove the disposable probe and helpers safely, then rerun affected decisive checks and reuse applicable unaffected evidence for the final state. Record final verification and omissions, not test chronology. Stop for changed owner/authority, unexplained failure, unavailable decisive environment, or non-convergence; within the same authorized scope use new failure evidence to diagnose and correct without an artificial Core handoff. No Git, review, archive, or external action follows from this method.
