# RSP Shape

Choose the branch before loading detail: bounded design advice is read-only and may have no Change; explicit planning-artifact work shapes or refines a Change/Group. Neither branch implements product behavior.

Shape owns decision clarification and planning artifacts even when their output is Markdown; approval of material choices stays with the authorized DecisionOwner. Doc may support wording settled decisions; final work-record convergence belongs to writing, not replanning. A material unresolved decision returns to Shape rather than being resolved by prose cleanup.

Responses follow explicit instruction, personal instructions, then conversation language. Preserve existing artifact language and canonical identifiers, commands and values. New artifacts follow explicit instruction, effective configuration, scoped project instructions, then conversation language. Resolve needed RSP settings through the selected CLI's successful `rsp config --json` summary, including defaults and inheritance; refresh on relevant drift or recovery. Raw YAML is diagnostic only. Failed projection leaves dependent choices unresolved while independent authorized work continues; resolve material conflicts with the owner. Core is not required.

## Establish the boundary

Read the request, authority, nearest project context, Change and Brief when selected, then only decisive evidence. A direct design question without a Change does not require one. A design question inside a tracked Change retains that WorkRef, but defaults to report-only; only explicit artifact authority permits updating its Design.

A request to shape, create, or refine a Change grants artifact authority unless no-edit; advice does not. If creation focuses it, preserve the exact prior focus and restore it immediately unless selection was requested. Shaping grants no other authority; preserve unrelated work.

Route concrete or ready work to implementation only when authorized and no design/planning question remains. An explicit read-only design request still ends with its report. Do not rewrite settled work for style or completeness.

## Resolve material ambiguity

Inspect the repository before asking. Ask only for an owner decision changing behavior, data, interfaces, compatibility, safety, ownership, migration, or acceptance. Write only authorized answers.

Derive requirements and acceptance checks from settled authority, not a preferred implementation. Do not promote an unsettled public behavior, failure contract, default or compatibility choice into an accepted requirement or mandatory check. Keep replaceable internal choices in Design; label material alternatives as proposals and retain any readiness-blocking decision in Blockers. Ordinary implementation details within the accepted contract need no new owner decision.

Choose permitted methods within the branch. Recover a diagnosed read/search fault against unchanged goal, scope, authority, baseline and evidence. Inspect artifact/focus effects before replaying planning mutations; unknown effects or unsafe replay stop that action. Required RSP commands/checks cannot be replaced by prose or tool status.

Ask one to three related material questions ordinarily, one DecisionOwner question per turn for deep clarification. Resume unresolved decisions from fresh facts and return the ready owner to Core; a method change alone restarts no workflow.

For a bounded design question, load only the relevant [domain modeling](references/domain-modeling.md), [module and seam design](references/module-seams.md), or [reversible exploration](references/reversible-exploration.md) method. Read [deep clarification](references/deep-clarification.md) only for explicit rigorous challenge or dependent high-risk decisions. Advice does not create or modify an artifact, authorize a disposable code probe, or turn a recommendation into product authority.

Read [external issue input](references/external-issue-input.md) only when a Change declares an issue relationship or the request asks to shape from an issue URL.

Never invent a product decision. When a material choice or mutation authority remains unresolved, leave the work open and report the single highest-impact blocker.

## Choose the owner

For authorized planning-artifact work, read [planning and readiness](references/planning.md) before choosing or naming an owner, writing a Change/Group, or updating the selected Design. It supplies WorkRef naming, Change granularity, the six-section contract and the Shape Ready gate. Read-only design advice needs none of those artifact procedures.

Read [complex shaping](references/complex-shaping.md) for qualified coordinated planning, multi-round clarification, slices sharing a completion contract or independently closable owners converging on terminal delivery.

## Apply the Shape Ready gate

For planning, apply the complete [Shape Ready gate](references/planning.md#apply-the-shape-ready-gate), then run the focused RSP check after authorized mutation. On pass, return the ready Change WorkRef or Group reference, artifacts and decisive evidence for Core to continue the authorized objective without another user request.

For read-only design, lead with the recommendation and decisive evidence. Include credible tradeoffs, owner decisions and a next action only when relevant to the current question; do not restate settled context or force a planning report. Create or mutate no plan automatically.

When a material decision prevents readiness, stop with decisive evidence, the DecisionOwner and required answer; resume from fresh relevant evidence after that answer. For other blockers, state the actual missing input, next owner and safe resume condition. Use canonical machine fields such as `StopDisposition` only when a real consumer requires them. Do not relabel unresolved fog as ready work.
