# Conditional coordination qualification

Load only after Core sees an actual obligation: independently owned slices or acceptance; interruption/recovery; host isolation or compatible continuation needed for the task; conflicting writers or scarce verification resources; real-host/provider/hardware validation; bounded review convergence; or coordinated lifecycle delivery. Ordinary single-owner work, file count, elapsed time, a failed check with an in-scope discriminating correction, and a ready successor without requested authority do not activate this branch. Coordination need not imply delegation or concurrency. Fixed read-only Review, release documentation, and bounded design advice remain their own responsibilities.

Resolve the smallest ready WorkOwner and exact goal/authority first; inspect dirty paths when changing owners. A Group needs direct children and a real shared completion obligation; owner overlap never transfers implicitly. Read effective manage.activation and manage.closeout from rsp config --json or .rsp/config.yaml, never rsp status (which does not project configuration). An absent setting retains explicit/local compatibility; invalid configuration fails closed as explicit/manual. Under explicit, enter coordination only on an explicitly managed request; under auto, still require the observed obligation. Activation grants no planning, product, Git, remote or external authority. Closeout is a limited grant only on the currently selected and qualified branch, subject to nearer denial and fresh gates. If qualification fails, continue ordinarily without further coordination resources.

On selection retain goal and authority in Core; no persisted controller. Pass only bounded work, owner, authority, decisive signal and return boundary to the relevant capability. Load coordination.md when actual workers/resources/independent acceptance are involved; coordination-recovery.md for interruption or recovery; coordination-review.md for repeated accepted findings; closeout.md only after current qualified eligibility. A required Fix worker may also own ordinary checks. Only explicitly independent Verify or Review requires a distinct worker from the accepted implementer; host observations prove attribution and independence, never self-report. Unavailable required capability stops acceptance incomplete.

Every manage.closeout preset is dormant on unselected, declined or unavailable coordination. For selected work, effective closeout remains a limited grant ceiling narrowed by nearer authority; review-clean, durable writeback, fresh rsp ready gates and exact scope remain prerequisites. Selection alone does not authorize push or publication. Report selection and the decisive signal when it matters, not a routine phase receipt.
