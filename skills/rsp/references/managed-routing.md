# Conditional coordination qualification

Load only after Core sees an actual obligation: independently owned slices or acceptance; interruption/recovery; host isolation or compatible continuation needed for the task; conflicting writers or scarce verification resources; real-host/provider/hardware validation; bounded review convergence; or coordinated lifecycle delivery. Ordinary single-owner work, file count, elapsed time, a failed check with an in-scope discriminating correction, and a ready successor without requested authority do not activate this branch. Coordination need not imply delegation or concurrency. Fixed read-only Review, release documentation, and bounded design advice remain their own responsibilities.

## Qualify the current owner

Resolve the smallest ready WorkOwner, exact goal and authority; inspect dirty paths when changing owners. A Group needs direct children and a real shared completion obligation. Overlap never transfers ownership.

Read effective `manage.activation` and `manage.closeout` from the same selected CLI's successful `rsp config --json` summary; optional `--compact` changes presentation only. The CLI validates and resolves compatibility defaults: omitted settings yield `explicit/local`. Invalid configuration produces a refusal, not a validated `explicit/manual` summary. Raw `.rsp/config.yaml` inspection is diagnostic, never an effective-policy substitute.

Refresh on configuration drift, recovery or dependent closeout. If projection fails or is unavailable, report the gap and stop configuration-dependent selection or automatic closeout; independently authorized work needing no unresolved setting may continue. Do not bypass validation or hand-compute defaults. Under `explicit`, enter only for an explicitly managed request; under `auto`, still require the observed obligation. If qualification fails, continue ordinarily without further coordination resources.

Activation grants no planning, product, Git, remote or external authority. Closeout is a limited ceiling only on the selected and qualified branch, subject to nearer denial and fresh gates.

## Select only the needed procedure

Core retains goal and authority without a persisted controller. Pass bounded work, owner, authority, decisive signal and return boundary to the capability. Load coordination.md for actual workers, resources or independent acceptance; coordination-recovery.md for interruption or recovery; coordination-review.md for repeated accepted findings; closeout.md after current qualified eligibility.

A required Fix worker may own ordinary checks. Explicitly independent Verify or Review needs a distinct worker from the accepted implementer, proved by host observations rather than self-report. If unavailable, acceptance remains incomplete; replacing an execution tool does not replace that evidence.

Every manage.closeout preset is dormant on unselected, declined or unavailable coordination. For selected work, effective closeout remains a limited grant ceiling narrowed by nearer authority; review-clean, durable writeback, fresh rsp ready gates and exact scope remain prerequisites. Selection alone does not authorize push or publication. Report selection and the decisive signal when it matters, not a routine phase receipt.
