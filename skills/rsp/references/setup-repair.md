# Setup and repair

Load this reference only before initializing, auditing, migrating, or repairing RSP-managed state.

1. Initialize with `npx -y @oevery/rsp init [--agents-mode managed|print] [--with-project-setup]`.
2. `--with-project-setup` creates and focuses `changes/project-setup.md`. Without it, create that Change only when explicit bootstrap tracking is still needed.
3. Put project-wide boundaries in `.rsp/specs/design.md`, use `rsp specs` for direct current-file navigation and bounded literal discovery, put cohesive reusable facts in the smallest domain Spec, and keep stable operating instructions in the nearest project-owned `AGENTS.md` outside its managed block.
4. Diagnose with `npx -y @oevery/rsp doctor`. It reads optional Broker discovery, the exact checkout runtime database, and bounded context freshness without starting Broker or creating an absent cache. Apply only deterministic repository repairs with `doctor --fix` or `rsp update`; `fixed` entries are real filesystem mutations, while an empty list means nothing changed.
5. Do not use repair commands to decide stale focus, semantic durable updates, or archive readiness.
6. Inspect optional runtime discovery with `rsp broker status --json`; absent status is non-mutating and must not create a cache. Use `rsp broker stop` only with explicit runtime-cleanup authority. It cooperatively stops a healthy compatible owner or removes identity-verified stale metadata without signaling a dead or reused PID; an incompatible owner requires the matching compatible package rather than manual PID signaling.
7. A Broker project session may lazily own one `runtime-v1.sqlite` database under its exact checkout namespace. Preserve an incompatible, incomplete, or corrupt database for diagnostics unless project-local runtime disposal is explicitly authorized. Close the exact owning Broker/session/store handles, then import `resolveRuntimeDisposalTarget()` and `disposeRuntimeDatabase()` from `@oevery/rsp/dist/runtime-store.mjs`; derive only the current checkout namespace and dispose that exact target. Repository update and doctor inspection never delete runtime state. Never hand-delete runtime files, remove the Broker cache root, guess another project identity, edit SQLite tables manually, copy a database across repositories or worktrees, signal a recorded PID manually, or treat events, receipts, checkpoints, or context packets as Change truth.
8. The default package has no Web bootstrap, bearer, browser snapshot, or Web recovery state. Do not recreate those retired delivery paths through repository configuration, logs, recovery notes, or durable context.

For manual audit, require `.rsp/`, managed roots, and nested Spec parents to be real directories. Require the project `AGENTS.md`, managed markers, fallback/config files, `specs/design.md`, placeholders, and any reserved generated-index compatibility path to be regular files. Confirm the managed block, direct Specs query, configured Decision Record exclusion, valid group briefs and direct children, supported path depth, and focus markers matching executable Changes. Symlinks, special files, incomplete inspection, unrecognized reserved indexes, and file/directory identity collisions fail closed. Fresh initialization and Spec creation never generate indexes. `rsp update` removes only a root `INDEX.md` or any `00-index.md` with exact generated Specs metadata, using complete preflight, quarantine, direct-query postcheck, and rollback; owner-controlled reserved content is preserved for explicit review.
