# RSP Manage

Manage one selected ready Change or shallow Change Group only after the user explicitly requests managed continuation. Keep RSP artifacts as durable truth and process data transient.

## Qualify before mutation

Require sufficient mutation authority and one selected owner: one focused ready Change, or one explicitly selected shallow Group whose direct Changes are shape-ready. Snapshot the user authority, nearest instructions and context, the Change or Group Brief and children, relevant Specs and Decisions, `rsp status --json`, and worktree once.

For one Change require at least two non-overlapping mutation scopes with independent verification, genuinely long authorized continuation, or interruption recovery whose stale-evidence cost justifies orchestration. For one Group require at least two ready direct children, or an evidenced long or recovery path across its children. A small single slice, tightly coupled scopes, or host worker availability alone is ineligible. On decline, make no mutation, create no dispatch envelope, receipt, budget, or controller state, and return the exact Core or Discipline next action without executing it.

Name allowed mutations, verification, unavailable acceptance, and external-action boundaries. Release identity is unconfirmed unless explicit user or repository authority supplies it. Preserve unrelated work. Default to four worker dispatches and one corrective retry per run.

## Dispatch owned work

Send an internal compact envelope only for real work:

```md
- WorkRef: <selected Change or executable Group child>
- Objective: <one observable slice>
- Authority: <exact inputs and allowed mutations>
- Return: <changed artifacts, decisive verification, omissions, stop boundary>
```

For a Group, dispatch only child WorkRefs in the current derived `plan.waves` wave. Parallelize only non-overlapping mutations with independent verification. Treat shared paths, lockfiles, generated artifacts, and broad integration outputs as overlapping unless isolated workspaces are explicitly authorized and available. Keep overlaps, blockers, later waves, and dependent verification sequential. Workers receive no implied focus, lifecycle, durable-write, Git, publication, deployment, approval, or cleanup authority.

Choose the cheapest decisive check per WorkRef. Run at most one broader integration gate after combined mutation when required.

## Continue from evidence

Inspect each diff and fresh verification. Accept only output owned by that WorkRef with passing decisive checks and named omissions. For a Group, rerun `rsp status --json`, restrict it to declared children, and continue only with the newly derived ready wave after progress.

Use the corrective retry only when new evidence identifies an in-scope correction. Otherwise stop. During interruption recovery, reread current authority and referenced evidence, return changed or unverifiable claims to pending, and enforce remaining limits. Handoffs are transient pointers; never create durable controller status, retry graphs, receipts, or parallel lifecycle state.

## Preserve boundaries

Keep dispatch chronology out of Changes, Group Briefs, Specs, Decision Records, and the final result. Update each executable Change only with converged requirements, outcomes, decisive evidence, omissions, and blockers. Keep shared completion in the Brief without copying child tasks or live state. Durable facts and rationale use Core routing.

Archive guidance is advisory without explicit lifecycle-closeout authority and Core's durable decision. Archive never grants Git or publication authority. With explicit Git authority, commit completed Changes as independently reviewable logical units after closeout. Return to Core before a separate release operation and dedicated release commit. Otherwise return exact per-Change commit boundaries and owners.

Stop at unresolved owner decisions, unavailable dependencies or acceptance, missing external-action authority, uncorrectable verification, drift, or exhausted limits.

Return only completed and pending WorkRefs or slices, fresh verification, omissions, the real boundary owner, and one next action. Do not expose retry or budget chronology or claim Group closure, archive, Git, publication, deployment, approval, or human acceptance without explicit authority and observed completion.
