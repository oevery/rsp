# Semantic concision

Reduce context only after naming the behavior that must remain equivalent. Compare the complete package, not `SKILL.md` in isolation.

Use rsp-doc's expression rules and Skill branch. This reference owns the maintainer comparison boundary, not another writing guide. Preserve the selected corpus scope; record intentional contract changes in the Change rather than calling them equivalent compression.

## Select the smallest correction

Identify the stable contract owner before changing its executable guidance. Where Specs overlap, consolidate the existing owner first; keep execution methods in Skills and source/benefit evidence in research. Then classify each candidate by its decision effect: retain, merge, conditional-load or remove. Keep necessary standalone authority/safety local; merge repeated explanations and load branch-only mechanics when needed.

Before adding a restriction, distinguish a contract gap from composition/context, fixture/tool failure, model noncompliance or unresolved attribution. Violating an existing rule does not demonstrate a missing rule; correct the responsible layer. Record decisions in existing audit/Change evidence.

## Equivalence check

Compare current and candidate for trigger, inputs, authority, action order, outputs, stops, verification, conditional loading, and failure/acceptance boundaries. Trace an ordinary task and each changed branch through the needed resources, handoffs and final answer, including independent package use. A removed entry paragraph is not a saving if every task still loads it elsewhere. Retain uncertain high-risk constraints until evidence supports removal.

Treat word, line, byte, token, and repetition deltas as diagnostics, not model equivalence. For a selected behavior comparison, judge action, correct non-action and wrong stops before cost. A smaller candidate with weaker compliance or boundary behavior is a regression.
