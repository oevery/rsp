# Adapt strategy

Use for individual skills or small behavior-shaping assets that may be reused with RSP-specific modifications.

## Examine

- Exact source paths, license, triggers, outputs, scripts, and behavioral invariants.
- Which upstream behavior already solves a demonstrated RSP problem.
- Which local constraints must override or remove upstream behavior.

## Report

- Identify the smallest reusable asset; do not adopt an entire methodology to obtain one skill.
- Complete `License and Reuse`; if the license is unknown or incompatible, limit the recommendation to model-only or independent reimplementation.
- Separate preserved behavior, proposed local modifications, and rejected behavior.
- Recommend provenance fields for a future derived asset: source report, recommendation ID, source path and base revision, or dated web snapshot identity with URL, content hash and retained source location.
- Select evidence for the changed behavior and intended claim, including a relevant restraint case when authority or scope changes. Single-candidate task execution with independent review can establish acceptance; old-versus-new comparisons and holdouts are optional research designs. Cost claims need comparable task outcomes and token, tool-call and elapsed-time evidence.

Do not create the derived skill during research. A selected recommendation must enter a separate RSP change and use a three-way update model for later upstream revisions.
