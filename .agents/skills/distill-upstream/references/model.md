# Model strategy

Use for peer workflow systems whose value is their domain model, artifact graph, directory semantics, constraints, or interaction design.

## Examine

- Domain entities and relationships.
- Stable invariants and ownership seams.
- Artifact dependencies and lifecycle semantics.
- Core versus optional capability layering.
- Directory structure as a reflection of the model.

## Report

- Translate concepts into RSP vocabulary instead of copying command names or file trees.
- Compare each mechanism against RSP's current model and a concrete local limitation.
- State what should remain intentionally different.
- Recommend a design experiment or normal RSP change, never an automatic product edit.

Treat feature parity as a non-goal. Prefer the smallest model correction that preserves RSP's single-file change and open-to-archived lifecycle.
