# Conform strategy

Use for standards that RSP should comply with rather than reinterpret.

## Examine

- Normative requirements, required metadata, path conventions, and compatibility limits.
- Current RSP behavior that can be checked mechanically.
- Version changes that alter validation or portability.

## Report

- Record each applicable requirement with exact upstream evidence.
- Classify RSP as conforming, non-conforming, or not applicable.
- Recommend validators or compatibility tests before prose rules.
- Reject product-specific conventions that are not part of the standard.

Do not copy explanatory standard text into runtime skills when a validator or concise compatibility rule is sufficient.
