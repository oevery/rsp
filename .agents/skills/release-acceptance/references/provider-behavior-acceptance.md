# Provider behavior acceptance

Load only when provider-backed Skill acceptance is requested and execution/review cost is authorized. Use the paired campaign in `evals/README.md`, not a fixed run-count smoke as release proof.

1. Build and freeze source, built artifacts, case inputs, baseline/candidate Skill directories and isolated provider configuration. Preview with `mise exec -- pnpm run eval:plan -- --repetitions 2`. Select explicit cases for a scoped smoke; a smoke is not full release coverage.
2. Run `mise exec -- pnpm run eval:campaign -- --allow-live --baseline-skills <directory|none> --candidate-skills <directory> --model <model> --effort <effort> --config-file <isolated-config> --repetitions 2 --max-sessions <authorized-count>`. Supply explicit auth and private holdout registry/root only when required and authorized. `evals/holdout/README.md` owns private authorship, freeze and separately enforced read isolation. Never fabricate those attestations.
3. Preserve the campaign directory and all retained per-run artifacts privately under `evals/reports/`. A pending semantic review is inconclusive, not a passed campaign. Obtain fresh blind-packet-only decisions with authorized `node evals/runner/cli.mjs review-batch --allow-live --report <campaign.json> --config-file <isolated-config> --max-sessions <authorized-count>`, or import independently obtained decisions with `pnpm run eval:review -- --report <campaign.json> --decisions <decisions.json>`.
4. Require task and local boundary correctness, declared observed-exposure expectations, complete semantic dimensions (including external actions), and all current public/private suite coverage. Missing/truncated/unsupported evidence remains inconclusive. Reviewer identity, context isolation and holdout provenance are attestations, not cryptographic proof.

Baseline task failures remain diagnostic; candidate failures and inconclusive executions stop the campaign. No hidden retries or dropped failures. Resume only matching budget checkpoints with the documented `--resume` path; unresolved in-flight execution requires investigation. Metrics never override correctness, and token limits are set only when explicitly requested.

Execution/input identity changes require fresh authorized execution. Deterministic grading-only changes may use the offline revalidation path documented in `evals/README.md`. Preserve prior decisions and do not merge separate reports into release evidence. The release runner consumes evidence without launching providers or granting release approval.
