# Release Acceptance

Select the evidence needed for the current release decision. This maintainer capability sequences existing checks; it owns no third release test engine. Keep source/version identity, checked scope and missing evidence explicit.

- Read [local checks](references/deterministic-acceptance.md) for deterministic release validation.
- Read [Skill behavior](references/provider-behavior-acceptance.md) when relevant behavior changed and model cost is authorized.
- Read [comparison](references/provider-routing-comparison.md) only for an explicitly requested comparative experiment.
- Read [exact candidate](references/exact-candidate.md) when version and release surfaces are final.

Run shared build/package/terminal resources serially. Diagnose failures before continuing; preserve original reports and do not replace unknowns with nearby evidence. Missing realistic coverage is an explicit gap, not permission to claim success from prose or static checks. Updates to execution, inputs or composition require fresh execution before behavioral claims.

Return selected checks, source identity, results and omissions. Local success grants no model acceptance, archive, commit, tag, push, publication, approval or human acceptance. Stop before a separately unauthorized action.
