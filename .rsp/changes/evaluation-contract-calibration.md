# Change: evaluation-contract-calibration

## Proposal

Make the existing Skill evaluation accept contract-equivalent outcomes while preserving behavioral, evidence and authority boundaries. Align task assertions and semantic criteria, isolate calibration targets and establish attributable owner-decision evidence through the existing Harbor/Reward Kit path. Product Skills and historical labels/verdicts remain outside the evaluator correction.

## Spec
### MODIFIED
- Requirement: Deterministic acceptance checks observable results, declared output contracts and preserved authority. Replaceable wording, source structure, command spelling and reference-only error details do not establish task success or failure.
- Requirement: Owner-decision status is nonempty outcome text. Its meaning and successful agent execution are judged from the report and native actions; failed, unavailable or unexecuted checks do not pass that criterion. The verifier's current-snapshot check remains independent and cannot establish agent execution; missing required host evidence remains unavailable.
- Requirement: Prepared owner-decision calibration identifies maintained Oracle reference/sample execution as its candidate actor, without claiming Codex or Skill behavior. Runner-selected context and separately transported subprocess observations establish the evidence source; report assertions, claimed origins and command-shaped output do not. An empty recorder observes no check; a missing recorder is unavailable. Existing labels remain unchanged, and source context cannot be retroactively granted to a historical producer that did not supply it.
- Requirement: Judge semantic dimensions separately with a sufficient-quality standard. A material behavior, scope or evidence violation cannot be averaged away; harmless variations and additional grounded explanation are allowed.
- Requirement: Calibrate graders using correct alternatives and isolated consequential regressions. Replacing a complete implementation and observing any test failure cannot establish retained tests' discrimination of a named defect.
- Requirement: When a calibration declares target criteria, each native target score must match alongside component scores. Other failing dimensions cannot substitute; unavailable targets are unscored. Historical component-only expectations retain their original scope.
- Requirement: Distinguish current verification from durable regression protection. A missing permanent test blocks only explicit required protection or a material gap tied to changed behavior, with consequence, existing evidence and maintenance cost considered. Other useful test additions remain non-blocking suggestions.
- Requirement: Behavior checks retain failure effects: an invalid recovery keeps quarantine and blocks later wire writes; mixed valid/unknown targets reject before any packet. Independent protocol groups may be reordered, while group contents, encoding and packet multiplicity remain protected.
- Requirement: Preserve historical jobs, captured inputs, calibration labels and original conclusions. Offline checks establish verifier behavior only; unresolved semantic judgments and infrastructure errors remain distinct from task failure.
- Requirement: The authorized live follow-up retains the prior executor/judge models and reasoning settings, selected model metadata, seven Skills, one attempt, concurrency one and zero task retries. Freeze native inputs separately for calibration and Codex execution; preserve mismatches and unscored outcomes without changing labels or rerunning automatically. The preparation plan records the exact nineteen-task selection.

### Acceptance
#### Scenario: Equivalent correct outcome
- GIVEN a correct task solution with different error details, evidence locations or explanatory wording
- WHEN the revised deterministic verifier runs
- THEN it accepts contract-equivalent behavior without weakening rejection, state, wire or workspace checks.
#### Scenario: Real negative control
- GIVEN a solution with a transaction, recovery, preservation or authority defect
- WHEN the matching offline control runs
- THEN it fails for that consequential defect; semantic-only defects remain explicitly assigned to the judge.
#### Scenario: Calibration and historical interpretation
- GIVEN historical false rejections, correct alternatives, real defects and unchanged reserve samples
- WHEN offline calibration and the matrix inventory are updated
- THEN results identify their scoring responsibility and limitations without rewriting original runs or claiming model acceptance.
#### Scenario: A target missed despite matching totals
- GIVEN a publication-defect sample whose component scores match because another quality dimension failed
- WHEN its declared contract/scope target was incorrectly accepted
- THEN calibration reports a mismatch; a missing or errored target remains unscored.
#### Scenario: Current verification of unchanged correct behavior
- GIVEN correct mixed-protocol code, useful existing tests and an executed unknown-target probe
- WHEN no behavior changed and permanent probe retention is not required
- THEN lack of that additional permanent test does not block acceptance; actual unknown-target sends still fail the behavior contract.

## Design

Task-local checks validate observable behavior, declared output shapes and preserved state. Shared parsing and native schemas remain the integration boundary. Corrections accept legal Git filenames, equivalent command/evidence forms, empty protocol selections and independent group order while retaining packet multiplicity, rejection before sends and recovery quarantine. Confounded full-implementation mutation scoring was removed.

Quality judging separates contract/scope, regression value and evidence/restraint. Full acceptance retains threshold aggregation and unavailable-result handling. Optional expected_criteria compare named native scores as well as components; unrelated failed criteria cannot hide a missed target, and unavailable targets stay unscored. Historical component-only comparisons retain their original scope.

Prepared owner-decision calibration attributes maintained Oracle reference/sample execution through runner-owned context and a separate subprocess recorder. It preserves real command/exit evidence without requiring shell xtrace or treating self-written receipts as observed execution. The original Codex rubric still relies on native actions. Saved source context is reused only when originally captured; missing recorder transport stays unavailable.

The local controls cover report encoding, output-location/symlink boundaries, verifier isolation, real failed/unavailable/unexecuted outcomes, source-attribution confounds and faulty judges that miss exactly the selected criterion. Source and successful-wording selections use the existing seven owner samples; the complete deterministic corpus has 29 candidate samples.

The [recorded baseline and adjustment triggers](../../tests/skills/calibration/README.md#owner-decision-baseline-and-adjustment-triggers) bound the completed owner-decision scope. A new attributable counterexample or material model/evidence-path/contract change may justify separately selected diagnosis. The nineteen selected tasks comprised six quality cases, eleven affected tasks and two familiar reserves; they were known historical cases, not a blind holdout. No general reliability or human-label acceptance follows.

The later structural-report correction and current-suite check are retained in the archived [implementation-quality record](../archives/2026-10-20_implementation-quality-guidance.md). They do not recompute this Change's historical calibration or establish a matched Skill comparison.
