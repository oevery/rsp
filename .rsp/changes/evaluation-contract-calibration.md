## Spec

- Requirement: Deterministic acceptance checks observable results, declared output contracts and preserved authority. Replaceable wording, source structure, command spelling and reference-only error details do not establish task success or failure.
- Requirement: Owner-decision status is nonempty outcome text. - Requirement: Judge semantic dimensions separately with a sufficient-quality standard. A material behavior, scope or evidence violation cannot be averaged away; harmless variations and additional grounded explanation are allowed.
- Requirement: Calibrate graders using correct alternatives and isolated consequential regressions. Replacing a complete implementation and observing any test failure cannot establish retained tests' discrimination of a named defect.
- Requirement: When a calibration declares target criteria, each native target score must match alongside component scores. Other failing dimensions cannot substitute; unavailable targets are unscored. Historical component-only expectations retain their original scope.
- Requirement: Distinguish current verification from durable regression protection. A missing permanent test blocks only explicit required protection or a material gap tied to changed behavior, with consequence, existing evidence and maintenance cost considered. - Requirement: Behavior checks retain failure effects: an invalid recovery keeps quarantine and blocks later wire writes; mixed valid/unknown targets reject before any packet. Independent protocol groups may be reordered, while group contents, encoding and packet multiplicity remain protected.
- Requirement: Preserve historical jobs, captured inputs, calibration labels and original conclusions. Offline checks establish verifier behavior only; unresolved semantic judgments and infrastructure errors remain distinct from task failure.
- Requirement: The authorized live follow-up retains the prior executor/judge models and reasoning settings, selected model metadata, seven Skills, one attempt, concurrency one and zero task retries. #### Scenario: Real negative control
- GIVEN a solution with a transaction, recovery, preservation or authority defect
- WHEN the matching offline control runs
- THEN it fails for that consequential defect; semantic-only defects remain explicitly assigned to the judge.
#### Scenario: Calibration and historical interpretation
- GIVEN historical false rejections, correct alternatives, real defects and unchanged reserve samples
- WHEN offline calibration and the matrix inventory are updated
- THEN results identify their scoring responsibility and limitations without rewriting original runs or claiming model acceptance.
#### Scenario: A target missed despite matching totals
- GIVEN a publication-defect sample whose component scores match because another quality dimension failed
- WHEN its declared contract/scope target was incorrectly accepted
- THEN calibration reports a mismatch; a missing or errored target remains unscored.
#### Scenario: Current verification of unchanged correct behavior
- GIVEN correct mixed-protocol code, useful existing tests and an executed unknown-target probe
- WHEN no behavior changed and permanent probe retention is not required
- THEN lack of that additional permanent test does not block acceptance; actual unknown-target sends still fail the behavior contract.

## Design
Reuse shared report parsing, native task schemas and existing offline regression entrypoints. Review each task family for requirement provenance, equivalent forms and negative controls; document both repaired and deliberately retained strict checks. Remove confounded retained-test mutant grading rather than build a second mutation engine. Separate the six quality rubrics into behavior/scope, test value and evidence/restraint dimensions. Keep threshold-based full acceptance and existing unavailable-result reporting.

Use existing complex consumer-path tasks as a reserved regression selection for this edit. They are historical known cases, not a blind holdout or evidence of large-project reliability. Reserve true discovery/comment-quality holdouts for a later independently selected experiment. Keep candidate semantic labels unconfirmed unless a human actually reviews them.

Extend the existing calibration presenter with optional `expected_criteria`, comparing native criterion values rather than free-form explanations. Add isolated publication and truthful missing-protection samples plus unchanged-probe and unknown-target-send protocol samples. Keep the two existing noise transformations and component labels, adding their named target expectations. Make required noise regression protection explicit in task instructions and keep product correctness separate from test-value assessment.

Owner-decision is converged at the [recorded baseline](../../tests/skills/calibration/README.md#owner-decision-baseline-and-adjustment-triggers). The evidenced causes are evaluator overconstraint, incomplete or unattributed Oracle evidence, and calibration/rendering confounds. Existing Skills and observed native task execution supply no demonstrated rule or execution gap in this scope. The combined correction changed several presentation variables, so its individual causal contributions remain unmeasured.

The baseline retains successful-wording and execution-source selections, named-target comparisons and local transport/receipt/faulty-judge controls. The [frozen three-job observation](../../research/reports/2026-10-19T16-25-25Z.md) records models, parameters, original results and their limits. A new attributable counterexample, relevant model/judge/evidence-path change or material task-contract change can justify bounded diagnosis; none automatically authorizes another run or Skill change. General reliability limits and unconfirmed labels are not new blockers to this completed owner-decision round.
