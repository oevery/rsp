# Change: code-quality-baseline

## Proposal

Establish six baseline tasks covering receiver transaction tests, protocol simplification and redundant capture identities, each with a preservation control. Independently rewrite local case patterns without product code or private conversation bytes. Use native Harbor and the unchanged complete seven-Skill suite.

The user subsequently authorized one fresh job with the corrected matrix, keeping the original model and parameters, followed by deeper upstream distillation and recommendations. This authorizes evaluation and research artifacts, not Skill changes.

Non-goals: Skill revisions, downstream installation, broader reliability claims, automatic supplemental runs, regrades, commits, archives or remote delivery.

- Requirement: Execute one current-suite Codex job with six tasks, one attempt each, concurrency one and the existing zero-task-retry policy. Preserve failures, ungraded results, native trajectories and captured inputs. No automatic resume, regrade or supplement.
- Requirement: Retain that original job and execute exactly one separately authorized fresh job with the corrected matrix. Keep executor/judge models and settings, selected model metadata, seven Skills, environment resources, one attempt, concurrency one and zero task retries unchanged. Preserve every outcome; no further run, resume or regrade is authorized.
- Requirement: Compare current Skill rules, actual execution and primary upstream practices. Distinguish missing rules, non-loading or non-application, business-authority gaps and evaluator defects. Return bounded recommendations without editing Skills.

### Acceptance
#### Scenario: Baseline distinguishes quality from superficial simplicity
- GIVEN the unchanged current suite and six frozen tasks
- WHEN the authorized job completes or reports an execution gap
- THEN the report distinguishes correctness, protection, test discrimination, restraint and loading observations without treating old cases or schema checks as current acceptance.

## Design

Add native task directories and focused offline calibration under tests/code/tooling. Reuse workspace preservation and Reward Kit support. Keep task-specific checks with their tasks. Prompts contain business authority and output requirements, not historical diagnoses or Skill choreography. Use current job defaults for executor/judge routing. Native sibling inputs own the freeze; no second identity registry or test engine. Report gates validate structure and business behavior; semantic judgment owns whether findings are real, including justified corrections in an intended control. Retain sanitized findings in a dated research report and raw execution under ignored reports.
