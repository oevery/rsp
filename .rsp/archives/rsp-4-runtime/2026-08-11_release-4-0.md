# Change: rsp-4-runtime/release-4-0

## Proposal
- Outcome: Withdraw the superseded RSP 4.0 release boundary without creating a standing successor Release Change
- Why:
  - Default Web delivery has been withdrawn, leaving primarily optional or additive runtime and query capabilities.
  - Practical 3.x compatibility can be retained at low cost for legacy `--lite` invocation and ordinary Node 22 installation, while generated Specs indexes are package-owned derived files with explicit safe migration and a machine-readable replacement.
  - The stable WorkRef remains as the durable owner of the withdrawn boundary instead of being renamed or erased.
- Scope:
  - Record that no `4.0.0` candidate will be prepared from this Group.
  - Remove stale Web release dependencies and leave future release preparation to an explicit version-and-range-confirmed release operation.
  - Preserve accepted implementation and historical Decision Records without presenting retained Web source as delivered product.
- Non-goals:
  - Finalize any release candidate before its exact version and comparison range are explicitly confirmed.
  - Rewrite commits, archived Changes, historical decisions, or public release records.
  - Commit, tag, push, publish, deploy, mutate issues, or perform registry authentication.

## Spec
### MODIFIED
- Requirement: The planned 4.0 release boundary is explicitly withdrawn without losing accepted implementation history.
  - No package metadata, release prose, tag, or publication operation identifies the current result as 4.0.
  - A future compatible release is prepared directly from its exact candidate range unless material coordination later justifies a new Release Change.
  - Retained Web source remains non-delivered and historical Web decisions remain immutable evidence.

### Acceptance
#### Scenario: withdrawn release boundary
- GIVEN default Web delivery is omitted and practical 3.x compatibility is selected
- WHEN this Change completes
- THEN no 4.0 candidate or standing successor Release Change is retained, and future release preparation remains version-neutral until explicitly selected

## Design
- Approach:
  - Replace version-finalization work with one explicit cancellation and handoff record.
  - Keep the original WorkRef to preserve durable identity and use the repository's direct release-docs and dedicated release-commit flow only after a future candidate range is frozen.
- Boundaries:
  - This Change owns only withdrawal of its former release boundary.
  - `preserve-3-x-compatibility` owns compatibility implementation; no current Change owns a future version identity.
- Affected areas:
  - This Change and the sibling Group Brief.
- Constraints:
  - Do not rename this WorkRef or delete historical accepted outcomes.
  - Do not perform candidate, Git, publication, or external operations.
