# Change Group: manage-orchestration-beta

## Goal
- Upgrade RSP's automatic managed path so non-small goal requests enter a transient, authority-bounded Manage intake before Shape or managed execution, while preserving direct handling for explicit small work and specialist routes for Review, Release, and isolated Design.

## Scope
- Add a managed-intake route that produces only `ready`, `needs-shape`, `needs-owner`, or `out-of-goal` and never mutates product, planning, lifecycle, Git, or external state.
- Add ready-owner evidence-frontier execution with bounded Diagnose, Inspect, Fix, and Verify lanes, deterministic requalification, single-writer mutation boundaries, and no persisted controller state.
- Add deterministic compatibility and safety fixtures plus a bounded beta evaluation that measures the new route against a direct baseline without making empirical cost thresholds a release-authority gate.

## Shared Constraints
- Keep `rsp` as the thin policy gateway: it selects direct work, a specialist discipline, or Manage; it does not hold an execution frontier, dispatch workers, or preserve a goal state.
- Preserve `manage.activation: explicit | auto` as the only activation policy. In this beta, `auto` selects Manage intake for non-small goal requests; `explicit` requires an explicit managed request. No separate `manage.intake` configuration is introduced.
- Existing fixed-scope Review, release operations, and isolated Pre-Change Design continue to bypass Manage intake. Tiny settled work remains direct.
- Keep Change and Group artifacts as the only durable work truth. Do not create a frontier file, ticket map, ledger, worker registry, run identifier, ambient hook, numeric routing score, or new public Skill.
- Automatic selection grants no planning, product mutation, lifecycle, Git, publication, deployment, approval, or human-acceptance authority. Push and publication remain explicit.

## Slices
- `manage-orchestration-beta/managed-intake-routing`: Route non-small goal requests through a no-mutation Manage intake, return structured owner outcomes to Core, and preserve specialist and tiny-direct exceptions.
- `manage-orchestration-beta/evidence-frontier-execution`: For an intake-confirmed ready owner, classify runtime uncertainty and coordinate bounded read-only evidence, per-boundary Fix, independent Verify, requalification, and stop behavior.
- `manage-orchestration-beta/beta-evaluation`: Add behavior fixtures and a bounded immutable beta evaluation for routing, authority, recovery, worker isolation, and observed cost/outcome evidence.

## Completion Conditions
- [x] Under `manage.activation: auto`, a non-small goal without a ready owner enters no-mutation Manage intake; it reaches Shape only through an explicit `needs-shape` return, then requalifies after Shape.
- [x] Tiny settled work and explicit Review, Release, and isolated Design requests preserve their existing direct or specialist routes without controller artifacts.
- [x] A ready managed owner deterministically classifies evidence, owner-decision, fog, and out-of-goal cases; only bounded evidence lanes run before a permitted Fix, and all authority, writer, retry, review, and recovery limits remain intact.
- [x] Focused contracts, fallback synchronization, package checks, and one bounded beta holdout demonstrate route correctness, no durable controller state, and truthful measured omissions.

## Durable Outcomes
- Current facts: update `.rsp/specs/design.md` and user-facing routing documentation only after validated behavior changes.
- Lasting rationale: no Decision Record during beta; create one only if beta promotion makes automatic intake a stable architectural commitment.
