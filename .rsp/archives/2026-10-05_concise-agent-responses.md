# Change: concise-agent-responses

## Proposal

Make routine responses task-relative and reduce unnecessary instruction loading without losing facts, authority, evidence or standalone capability use.

Scope: the previously authorized global response-default update; RSP product response guidance and fallback; contract ownership in Workflow and Writing quality; all eight product and three maintainer Skill packages for necessity and reading-path inspection; the subsequently authorized Ponytail-only source refresh and provenance repair; the authorized runner evidence-chain repair and one fresh Doc execution/judgment. Current source work excludes personal instructions/configuration and preserves earlier dirty work and evaluation records.

Non-goals: new Skills or product runtime state, invocation/permission changes, new product machine schemas, weaker verification or Git safeguards, unrelated upstream refresh or baseline acceptance, Git delivery or publication, broad model matrices or unsupported efficiency claims.

## Spec

### MODIFIED

- [Workflow](../specs/workflow.md#core-flow) owns ordinary responsibility selection and continuation, separate from conditional coordination and lifecycle obligations. Its response contract requires necessary information, not a universal delivery template.
- [Writing quality](../specs/writing-quality.md#instruction-and-resource-design) owns decision-oriented instructions and reading paths. Merge or revise an existing rule before adding a parallel qualification; keep task-specific goals, necessary inputs, actions, completion evidence and real stops clear without mandatory headings.
- [Distribution](../specs/distribution.md#skill-package-boundaries) remains unchanged: each published package preserves necessary local guidance and conditional resources without depending on repository Specs, research or another mandatory installed package.
- Maintainer concision owns rule necessity and failure attribution. Research owns source and benefit evidence; an observed violation of an existing rule is not itself a missing product contract.

### Acceptance

- Normal responses answer the request; failures, risks, material decisions and unverified boundaries remain explicit. Review retains both perspective results, findings and coverage; Verify retains canonical outcomes/fields; Commit retains exact delivery observations and its complete message as evidence.
- Optimization preserves triggers, inputs, authority, actions, outputs, stops, required verification and standalone closure. Ordinary tasks do not load unrelated conditional procedures. Fixed output lengths, persistent modes and source-word quotas are not requirements.
- Source acceptance requires complete-package reading-path inspection, metadata/resource/document/security checks and selected offline readiness. The authorized model follow-up adds candidate-bound task judgments; the evidence repair adds runner checks and independent fixed-scope Code/Document review. Unnecessary reads/handoffs, wrong stops, restraint and final responses are inspected alongside successful paths.
- Static checks establish neither model behavior nor discovery, independence or cost benefit. Behavioral and comparative claims need separately authorized actual evidence bound to the relevant candidate.
- Original reports and frozen inputs retain their identities and verdicts. No current all-surface acceptance may be inferred from older candidate results.

## Design

The authorized evidence-chain repair retains sanitized session tool calls, returns and host tool items before isolated-home cleanup, without retaining session instructions or personal configuration. Independent review receives integrity-checked copies and a separately labelled literal argv view; recorded commands are never replayed. Missing or malformed session evidence remains an explicit gap, and older records remain reviewable without upgrading their verdicts. This runner-only repair does not change product Skills.

The earlier global file was an explicitly authorized external target, never a repository delivery input; this follow-up does not modify personal settings.

Contract convergence precedes Skill edits. Workflow consolidates ordinary routing; Writing quality provides the instruction-design contract; Distribution already supplies standalone closure. Core's existing qualification reference owns coordinated procedures, and its durable-writeback reference owns knowledge placement. Shape's existing complex method owns coordinated planning. Doc's existing Skill method projects the writing contract locally. Review/Audit use compact information requirements and illustrative examples, not forced report scaffolds. Implement expresses reuse before adding seams/tests. Verify, Commit, Distill and Release Acceptance retain their sufficient boundaries without forced edits.

No new runtime resource or shared dependency is introduced. The [contract/path report](../../research/evaluations/rsp-skill-runtime-context/2026-10-05-contract-path-convergence.md) owns corpus decisions, path inspection and candidate identities. Existing source research motivates mechanisms only; no upstream prose, hooks, mode or fixed response limit is copied. Uncertain high-risk gates remain.
