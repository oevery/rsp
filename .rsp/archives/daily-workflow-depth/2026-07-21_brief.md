# Change Group: daily-workflow-depth

## Goal
- Qualify a lightweight managed daily workflow before 3.0

## Scope
- Coordinate the smallest pre-3.0 follow-up selected by the Matt-first daily capability audit: deepen explicit shaping, evaluate an optional managed continuation owner, and freeze the product boundary through five representative journeys.
- Preserve the seven promoted Skills as the stable assisted suite; promote additional behavior only when paired evidence demonstrates a daily-workflow delta.

## Shared Constraints
- Keep ordinary invocation and instruction cost close to the current suite; disclose depth only when its branch is selected.
- Matt is the primary behavioral reference, while Superpowers, GSD, and Compound Engineering supply adversarial or controller evidence rather than mandatory runtime dependencies.
- Existing RSP Changes, Specs, Decisions, and verification receipts remain the only durable workflow truth.
- No child may infer commit, push, tag, publish, destructive cleanup, or unavailable human/environment acceptance authority.
- Keep the Group shallow: each child owns one independently reviewable output and the terminal slice alone owns cross-slice composition.

## Slices
- `daily-workflow-depth/deepen-rsp-shape`: add and qualify an explicit deep-clarification branch plus a narrow project-design capability return contract.
- `daily-workflow-depth/prototype-managed-controller`: independently prototype and evaluate an optional bounded Controller without changing durable RSP state or the stable seven-Skill suite.
- `daily-workflow-depth/validate-daily-workflow-depth`: integrate only demonstrated behavior, run the five-journey composition gate, report total cost and remaining limits, and freeze the 3.0 product boundary.

## Completion Conditions
- [x] All three child Changes are independently verified and archived in declared order.
- [x] Five sanitized journeys cover ambiguous intent, domain language, module seams, ordinary correction, and long multi-session continuation.
- [x] Promotion decisions distinguish stable suite, optional capability, and retained external/project-owned behavior without claiming untested coverage.
- [x] The release Change depends on the terminal child and contains no ambiguous daily-workflow blocker.

## Durable Outcomes
- Update the Skill System and Capability Model only for behavior that passes the terminal gate.
- Record rejected expansion and unqualified boundaries in the terminal evaluation report and release documentation inputs.
