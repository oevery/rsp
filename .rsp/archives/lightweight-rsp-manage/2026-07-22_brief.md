# Change Group: lightweight-rsp-manage

## Goal
- Add optional lightweight managed orchestration that increases autonomous continuation and bounded task delegation only where it demonstrates a material advantage over direct use of the existing eight-Skill suite.

## Scope
- Revise the research-only `rsp-manage` contract into an explicit-only controller for genuinely independent multi-slice work and interruption recovery.
- Qualify bounded delegation, recoverable failure, budget exhaustion, authority stops, package discovery, and context cost before deciding promotion.
- Keep the current 3.0 assisted suite and `release-3-0-0` independent; a later release decision may adopt a qualified optional controller.

## Shared Constraints
- One focused, ready Change and existing project/RSP artifacts remain authoritative; orchestration introduces no durable lifecycle, tracker, retry graph, or receipt store.
- Ordinary single-slice and tightly coupled work stays direct. Managed execution requires explicit user intent plus independence, long continuation, or real recovery cost.
- Workers receive exact inputs, mutation boundaries, expected output, verification, stop conditions, and finite budget. No worker gains focus, lifecycle, Git, publication, deployment, deletion, or approval authority.
- Preserve response-language behavior and return every result, blocker, verification omission, and durable routing decision to existing owners.

## Slices
- `lightweight-rsp-manage/refine-explicit-controller`: revise the candidate contract and deterministic restraint/dispatch/recovery behavior without promoting it.
- `lightweight-rsp-manage/validate-managed-orchestration`: forward-test the revised candidate on discriminating holdouts, decide promotion, and only then reconcile package/product truth.

## Completion Conditions
- [x] A non-leading long task and a real disjoint-worker forward test determine whether bounded orchestration improves on baseline; absent a demonstrated delta, retain the candidate under research.
- [x] Ordinary or tightly coupled work does not load managed overhead and returns to direct Core/Discipline behavior.
- [x] Interruption recovery rejects stale evidence and stops truthfully at unavailable human acceptance; corrective retry and budget exhaustion remain explicit promotion gates.
- [x] Promotion occurs only if task success/corrections or recovery quality improves enough to justify measured token, elapsed-time, output, and tool-call cost; this run therefore records `revise` without promotion.

## Durable Outcomes
- If promoted, update `.rsp/specs/design.md`, README, design philosophy, package inventory, and the reconciled Skill System/capability model. If not promoted, retain the revised candidate and honest evaluation under research only.

- none
