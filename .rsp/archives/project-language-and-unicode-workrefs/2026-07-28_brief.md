# Change Group: project-language-and-unicode-workrefs

## Goal
- Let a project declare deterministic RSP response and artifact languages while allowing safe Unicode WorkRefs and archive filenames, without duplicating language state in every Change or migrating existing history.

## Scope
- Coordinate one project-language contract and one Unicode identity contract across CLI configuration, generated artifacts, Core/Skill behavior, open work, Groups, focus, dependencies, archives, history, and reopen.
- Preserve response/artifact independence, exact user overrides, existing artifact language, and current ASCII projects.
- Keep visible Markdown section localization outside this Group; canonical section headings and their current parsers remain unchanged.

## Shared Constraints
- `.rsp/config.yaml` remains strict and fail-closed; JSON output exposes effective values without localizing machine keys or values.
- Existing Changes and archives are never renamed or translated automatically. Configuration changes affect new artifacts and response defaults only.
- Unicode identities use one canonical normalization and the existing flat-or-one-Group-depth model, reject unsafe/reserved segments, and preserve no-follow managed-path checks.
- Do not add a general localization framework, translation catalog, per-Change language duplication, localized internal section headings, or persisted controller state.

## Slices
- `project-language-and-unicode-workrefs/language-configuration`: Add the `language.default`, optional `language.response`, and optional `language.artifacts` project contract, effective projections, generated defaults, and Core/Skill behavior without per-Change repetition.
- `project-language-and-unicode-workrefs/unicode-workrefs`: Accept canonical safe Unicode WorkRefs and Group names across every identity consumer, preserving ASCII compatibility and exact Unicode archive/history/reopen behavior.

## Completion Conditions
- [x] In a project configured only with `language.default: zh-CN`, RSP derives Chinese response and artifact defaults without scanning archives or adding `language` to each Change.
- [x] A Change Group and child with Chinese WorkRefs can be created, focused, blocked by an exact dependency, archived, queried in history, and reopened without identity drift.
- [x] Existing ASCII projects, missing-language configuration, machine-readable JSON contracts, and legacy archives remain compatible.
- [x] Authored package sources, generated fallback behavior, Specs, and tests agree on the final language and identity contracts.

## Durable Outcomes
- Current facts: Update `.rsp/specs/core-model.md`, `.rsp/specs/cli-contracts.md`, and `.rsp/specs/skill-system.md` with the implemented project-language and Unicode identity contracts.
- Lasting rationale: No Decision Record unless implementation reveals a non-obvious irreversible compatibility choice beyond the accepted configuration and normalization model.

- none
