## Design
- One Change owns the shared asset-consistency outcome. Doc and maintainer authoring own prose; Implement owns executable scaffolds and their ordinary checks; independent Review remains read-only.
- Inspect complete canonical packages and direct reading/consumer paths, not just entrypoints or changed lines. Case semantic inspection follows the changed-risk boundaries; full-catalog offline readiness establishes no exhaustive oracle correctness or agent result.
- Preserve the [initial review](../../tests/skills/reports/asset-contract-audit/initial-review.md), [initial corrections](../../tests/skills/reports/asset-contract-audit/corrections.md), [full-audit corrections](../../tests/skills/reports/asset-contract-audit/full-audit-corrections.md) and [pre-AST re-review corrections](../../tests/skills/reports/asset-contract-audit/re-review-corrections.md) with their original identities and results. [AST integration evidence](../../tests/skills/reports/asset-contract-audit/ast-integration.md) owns the resumed candidate's coverage, applicability decisions and final judgments. Reports are local/ignored, not published acceptance.
- Existing Specs remain authoritative. Reuse the committed source-positioned document projections for scaffold integration; do not restore string normalization or duplicate hidden-content tests. Optional hints guide the writer without supplying content or changing Group eligibility.
- [Original targeted model evidence](../../tests/skills/reports/asset-contract-audit/model-validation.md) owns the initial three-case execution and judging. [Supplementary evidence](../../tests/skills/reports/asset-contract-audit/model-validation-followup.md) owns the repaired-harness CLI execution/judge, mixed-result historical reassessment and configuration-refusal reuse decision. Preserve all original verdicts and keep fresh execution, reassessment and reused evidence distinct; this coverage proves neither whole-corpus behavior nor repeated-run stability.
- Product projections keep local runtime closure; real maintainer packages remain outside the published inventory. Check authored/generated fallback equality and synchronize with the selected built CLI only if the authored fallback changes.
- The fixed real CLI case selects Core for declared ownerless exact-candidate checks. The mixed-result case retains failure and unavailable observations separately; the configuration-refusal case must preserve workflow and Git state. The separately authorized model run uses the existing runner and shared executor/judge settings, isolated task workspaces and private provider routing. Case declarations grant no additional authority, and these three cases do not establish maintainer behavior or natural discovery.
- Runner recovery follows event order, not error-message matching: a subsequent turn completion clears an intermediate stream error, while terminal turn failure, incomplete traces and process failures remain non-passing. Executor and judge share this observation; deterministic task failures remain failures. Isolated shell startup restores the runner Node path under the disposable provider HOME without changing host profiles or replacing the fixed real CLI snapshot. [Runner repair evidence](../../tests/skills/reports/asset-contract-audit/runner-repair.md) is separate from the immutable model records and grants no new provider budget.
