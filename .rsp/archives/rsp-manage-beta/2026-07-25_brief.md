# Change Group: rsp-manage-beta

## Goal
- Deliver an explicit-only, low-overhead `rsp-manage` in a locally verified `@oevery/rsp@3.1.0-beta.0` prerelease artifact ready for separately authorized npm beta publication and real-project dogfooding without moving npm `latest`.

## Scope
- Productize the evaluated research candidate, reduce avoidable orchestration and artifact overhead, integrate the Skill into package discovery, prepare truthful prerelease documentation, and prove exact-version clean installation and `npx` behavior.

## Shared Constraints
- Preserve RSP Changes, Specs, and project authority as the only durable workflow truth; do not add controller state, implicit invocation, automatic Git/publication actions, or broad synthetic evaluation matrices.
- Keep ordinary single-slice work on existing Core/Discipline paths, and retain tests or documentation only when they protect a public contract or stable user-facing fact.
- npm publication, dist-tag mutation, Git tag, push, GitHub Release, and boats-cloud repository mutation remain outside this Group's authority.

## Slices
- `rsp-manage-beta/productize-controller`: refine and promote the compact managed-controller Skill plus its public behavior and package-discovery contracts.
- `rsp-manage-beta/install-packaged-skills`: add a safe explicit CLI path that installs the exact package-bundled Skills into a project's `.agents/skills` without touching unrelated Skills.
- `rsp-manage-beta/prepare-beta-package`: set the prerelease identity, prepare the complete `v3.0.0..HEAD` net-release documentation, and prove the exact tarball/clean-install/npm-exec surface without publishing it.

## Completion Conditions
- [x] A clean installed `@oevery/rsp@3.1.0-beta.0` exposes the expected CLI and ten-Skill inventory including `rsp-manage`.
- [x] The same exact package can initialize a project and explicitly install its bundled Skill suite with conflict-safe dry-run and replacement behavior.
- [x] The beta documentation covers the complete `v3.0.0..HEAD` net change, Node 22+ migration, explicit manage invocation, eligibility, authority, known host/cost limitations, post-publication exact-version dogfooding, and the fact that npm `latest` remains unchanged until separately authorized publication or promotion.
- [x] Full release gates and fixed-scope Code, Document, and package review pass with no unresolved blocker.

## Durable Outcomes
- Current facts: `.rsp/specs/design.md`, `README.md`, and `README.zh-CN.md` after installed behavior is verified.
- Lasting rationale: no Decision Record expected; the explicit-only optional-controller boundary already follows the stable product layering and remains reversible during beta.
