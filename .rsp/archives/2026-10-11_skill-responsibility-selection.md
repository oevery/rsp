# Change: skill-responsibility-selection

## Proposal

Make RSP responsibility selection and shared work identities reliable across direct
Skill invocation. Install the seven core Skills as one suite, centralize shared
identity definitions, and incorporate bounded structural discovery into Review.
Align the evaluation host with retained model metadata so host truncation is not
mistaken for a Skill defect or addressed through unnecessary reading rules.

## Spec

### MODIFIED

- Select Review for fixed-scope semantic and completion judgment, including its
  authorized supporting checks. Select Verify for declared-check reporting or a
  separate verification obligation. Preserve explicit combined requests, required
  independent workers and Core's lifecycle ownership.
- Reuse applicable instructions in the same context; obtain missing or changed
  instructions before relying on them. Fresh workers load their own instructions.
- Install all seven core Skills together while allowing direct invocation. Shared
  WorkOwner, Change, Group and logical WorkRef definitions belong to Core's
  references/work-model.md. Missing shared resources stop dependent operations;
  file locations never replace logical WorkRefs in commands or report fields.
- Reject partial installation before mutation. Permit cross-Skill resource links
  only to Core references within the suite. Preserve unknown Skills and rollback
  protections; migrate retired audit identities to Review through explicit force.
- Interactive migration lists replacement and deletion directories before a
  separate confirmation, including deletion-only migrations. Cancellation leaves
  files unchanged; confirmation discloses loss of local customizations.
- Review owns structural discovery within an explicit repository/subtree boundary
  without requiring a diff. Ordinary review does not expand into a repository
  audit, and findings grant no repair, design, delivery or approval authority.
- Evaluation retains pinned Codex and selected model metadata, accepts valid
  file:line evidence, and attributes executor usage to root and descendant session
  identities. Missing usage remains unknown; judge usage is excluded. Loading and
  token counts are diagnostics, not behavioral acceptance gates.

### Scenario: Direct tracked review

- GIVEN the complete suite and a selected grouped Change
- WHEN Review is invoked directly to judge completion with a supporting check
- THEN it loads missing shared definitions, reports the logical WorkRef, and
  preserves judgment and independent-evidence obligations without executing Core.

### Scenario: Interactive migration

- GIVEN a retired audit directory, with or without divergent core Skills
- WHEN the user opens the installer
- THEN replacement and deletion directories are visible before confirmation;
  cancellation preserves all files and confirmation changes only the planned scope.

## Design

Each Skill retains its local action, authority and stop rules. Shared definitions
use one conditional reference without mandatory Core execution or a loader
registry. Structural lenses move to Review's conditional method. Installation's
existing preflight supplies the TUI's replacement/deletion plan, keeping migration
semantics in the installer.

The native Harbor adapter retains selected model metadata and corrects root
trajectory selection and descendant usage attribution. Task outcomes, preservation
and actual worker evidence judge behavior. The earlier tool-budget reading rules
were removed after host alignment; original model failures and comparisons remain
in the research reports rather than becoming runtime instructions.

Current contracts are recorded in [Distribution](../specs/distribution.md),
[Work model](../specs/work-model.md), [Workflow](../specs/workflow.md) and
[Writing quality](../specs/writing-quality.md), with aligned user and maintainer
instructions. No additional Decision Record is needed: this change refines those
owners without introducing a separate lifecycle or extension architecture.
