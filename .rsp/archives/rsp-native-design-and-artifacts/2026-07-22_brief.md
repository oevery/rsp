# Change Group: rsp-native-design-and-artifacts

## Goal
- Make RSP own design resolution and durable artifact handoff without importing a heavy external workflow.

## Scope
- Promote one concise RSP-native design discipline that resolves domain, module, and reversible exploration questions against an existing WorkRef.
- Make durable artifact routing and recoverable continuation explicit product behavior instead of relying on separately installed writing or handoff Skills.
- Keep generic Git conflict mechanics, delivery side effects, host orchestration, and platform tooling outside the published RSP capability surface while providing a compact safe fallback where RSP execution encounters them.
- Qualify the revised installed suite before `release-3-0-0` can proceed.

## Shared Constraints
- Distill mechanisms from accepted upstream evidence; do not copy an upstream suite or introduce runtime dependencies on it.
- Current RSP Changes, Specs, Decision Records, project-owned instructions, and context files retain their existing semantic owners.
- Planned design belongs in the selected Change; current facts and lasting rationale are written only through the Core durable decision under explicit mutation authority.
- Skills remain concise, independently invocable, portable, and free of hidden state, recursive orchestration, or implicit Git/publication authority.
- Human-facing artifact and report prose follows the requested, project, existing-artifact, then conversation language order.

## Slices
- `rsp-native-design-and-artifacts/promote-rsp-design`: independently implement and qualify the RSP-native design discipline plus its progressive design references.
- `rsp-native-design-and-artifacts/strengthen-artifact-continuation`: independently tighten durable artifact writing, bounded handoff, and compact Git-conflict fallback contracts in existing Core and execution Skills.
- `rsp-native-design-and-artifacts/validate-native-design-composition`: integrate both capability slices, validate installed composition and package discovery, reconcile product documentation/model truth, and gate the 3.0 release.

## Completion Conditions
- [x] A clean installed package can shape one tracked design question, resolve it through `rsp-design`, implement the selected result, review it, and make the correct durable-writeback decision without requiring Matt, Superpowers, or Compound Skills.
- [x] Design, current-fact, rationale, project-context, and temporary-continuation outputs route to exactly one existing semantic owner and do not create a second lifecycle or hidden receipt store.
- [x] Ordinary Git conflicts have a compact safe model fallback while complex or out-of-scope conflicts stop without speculative resolution or inferred Git authority.
- [x] Static conformance, behavior/restraint fixtures, context-cost evidence, build, lint, tests, release checks, and clean-install Skill discovery all pass for the revised suite.

## Durable Outcomes
- Update `.rsp/specs/design.md`, `README.md`, `docs/design-philosophy.md`, and the reconciled Skill System/capability model to describe the promoted design discipline and artifact ownership boundary.
- Record the user-selected design/artifact boundary in a Decision Record only if implementation exposes a hard-to-reverse choice not already durably explained by those owners.

## Blockers
- none
