# Change Group: 3-0-skill-readiness

## Goal
- Raise the RSP 3.0 Skill Suite from a manually composable minimum to an assisted engineering loop that can route failed work, resolve review findings, recover context, and prove the combined behavior before release preparation resumes.

## Scope
- Coordinate three independently verifiable capability slices: discipline routing, review resolution plus handoff, and an end-to-end assisted-loop evaluation.
- Establish the release-readiness evidence consumed by `release-3-0-0`; this Group does not perform versioning, packaging, commit, push, tag, publish, or release operations.

## Shared Constraints
- Preserve `.rsp/` artifacts and project instructions as authority; Skills may route or hand off work but must not create a parallel lifecycle or hidden durable state.
- Keep canonical Skill behavior host-neutral and useful without optional external Skills; installed diagnosis, TDD, or review capabilities may be selected explicitly but never assumed.
- Do not copy Matt or Superpowers catalogs for breadth alone; add only behavior needed to close a demonstrated RSP engineering-loop gap.
- Preserve explicit Git, publication, deployment, approval, deletion, and external-action authority boundaries.

## Slices
- `3-0-skill-readiness/integrate-diagnosis-tdd-routing`: define and verify deterministic routing from implementation evidence to optional diagnosis or TDD disciplines with a safe manual fallback.
- `3-0-skill-readiness/close-review-resolution-handoff`: define and verify finding disposition, fix/re-review return ownership, and a minimal recoverable handoff contract.
- `3-0-skill-readiness/validate-assisted-engineering-loop`: build representative cross-skill scenarios and report whether the assisted loop meets the tightened 3.0 release gate.

## Completion Conditions
- [x] All three child Changes are archived and their focused checks pass.
- [x] The evaluation exercises shaping, implementation failure, discipline routing, review disposition and correction, re-review, and context recovery without hidden state or implicit Git authority.
- [x] The release Change truthfully depends on this Group's validated outcome before release preparation resumes.

## Durable Outcomes
- Update `research/models/rsp-skill-system.md` and the relevant capability model with the promoted assisted-loop contracts and retained deferred boundaries.
- Update `.rsp/specs/design.md` only for stable shipped behavior that future maintainers must treat as current product truth.
