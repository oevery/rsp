# CLI Contracts

## Purpose
- Define deterministic command, filesystem-safety, inspection, JSON, history, direct Specs-query, and repair behavior outside the interactive TUI.

## Stable Facts
- One WorkRef-tree inspection owns open-work discovery for `check`, `status`, and `doctor`; unsupported directories, non-Markdown entries, symlinks, file/directory collisions, and incomplete reads are reported consistently.
- `.rsp/changes/` and existing `focus.d/`, `archives/`, and direct Group prefixes must be real directories. Invalid roots and prefixes fail closed before reads or mutations; `rsp update` and `rsp doctor --fix` may restore a missing changes root.
- One managed-path module owns no-follow inspection, safe parent-chain resolution, and regular-file discovery for the RSP root, WorkRefs, initialization, repair, Spec creation, archive discovery, and direct Specs queries.
- Archive discovery accepts only flat files or one real Group directory. Specs may recurse through real directories and regular files; symlinked or special entries are invalid.
- Final managed files—including project `AGENTS.md`, focus markers, fallback/config, placeholders, generated project files, and any reserved generated-index compatibility path—must be missing or regular files. Initialization and update preflight `AGENTS.md` before other managed mutations.
- `rsp status` fails visibly when current work is invalid, a focus target is missing, or open work cannot be read. It derives exact dependency edges and reasons, minimal graph nodes, blockers, ready Changes, and stable waves from authoritative artifacts.
- Read-only status keeps canonical WorkRef identity separate from human-readable summary. Every open Change JSON record exposes `summary: string | null` from frontmatter `summary`, otherwise Proposal `Outcome`, otherwise Proposal `Summary`; every Group exposes the first meaningful `Goal` item. Empty and untouched `<…>` summary content projects as `null` without changing structural diagnostics.
- `.rsp/config.yaml` accepts strict `manage.activation` values `explicit | auto`, `manage.closeout` values `manual | lifecycle | local`, `workspace.activation` values `auto | explicit | disabled`, and one strict durable `language` mapping with `default`, `artifacts`, and `commit` language tags. The canonical generated defaults are Manage `auto + local` and Workspace `auto`; `language.default` is active while the optional `artifacts` and `commit` overrides remain visible as commented examples until configured. `rsp init` writes the complete default mapping, while `rsp update` backfills missing defaults only after validation and never overwrites existing values. Legacy projects without a config file receive the generated defaults; malformed YAML, missing required fields, `language.response`, wrong shapes, unknown keys, and invalid values fail closed before config mutation.
- Plain status shows configured effective artifact and commit languages when present. JSON status always exposes stable `language.artifacts` and `language.commit` string-or-null values; compact JSON is equivalent and has no response-language field. These values are durable project preferences, not host-wide chat settings, machine-output localization, or Git authority.
- Plain status renders a present Change or Group summary as secondary text while retaining the exact WorkRef as the command and selection identity.
- Artifact-creation commands remain deterministic for every valid BCP 47 preference: generated scaffolds contain canonical structural tokens, neutral unfinished placeholders, and verbatim user input rather than a bounded locale catalog or an implicit English prose fallback. Placeholder diagnostics continue to prevent untouched scaffolds from appearing complete.
- For one compatible-release cycle, `rsp create --lite`, `--lite=true`, and `--lite=false` are accepted as deprecated inputs. They emit one bounded warning, remove only the recognized compatibility token before command parsing, and create the same kind-aware six-section scaffold through the single standard renderer. Every other `--lite=` token fails before Change or focus mutation.
- `rsp create <name> [summary] --issue <url>` validates and stores one normalized `relates` issue relationship without remote access. `--issue-relation closes` records explicit closing intent and is invalid without `--issue`; all issue input is validated before Change or focus mutation. Supplying issue options for an existing Change fails explicitly and never adds update semantics or mutates the existing Change or focus.
- `rsp check` reports stable errors for malformed, unsafe, duplicate, or unsupported issue metadata in open Changes. JSON status and show always project each valid open Change's normalized issue relationships; JSON history list/detail preserves valid v1 relationships for archived Changes, while plain show and history detail render them without fetching remote data. Immutable archives with absent or non-v1 `issues` metadata remain readable and omit the issue projection rather than failing complete history/status inspection.
- New `rsp init` config templates select Manage `auto + local` and Workspace `auto`; `rsp update` reconciles older templates to the same complete default shape while retaining explicit project customizations.
- Plain `rsp status --verbose` shows resolved Manage and Workspace policy values plus the dependency forest; default plain status keeps the compact current-work summary. JSON status exposes the same effective `manage.activation`, `manage.closeout`, and `workspace.activation` values regardless of plain presentation mode. A valid legacy config without Workspace resolves to `auto`; invalid configuration resolves Workspace to `disabled`. These are inspectable configuration and derived state, not persisted run or controller state.
- Filtered status retains the selected Changes' transitive prerequisites and distinguishes selected nodes from prerequisite context. Verbose plain output renders the same graph as a deterministic dependency forest; JSON remains the canonical flat projection.
- CLI commands own deterministic filesystem operations, structural checks, direct bounded Specs projections, and warnings. Semantic durable-writeback decisions remain outside the CLI.
- Production commands import cohesive Core owners directly; a focused runtime-import graph check ignores type-only imports and rejects multi-module Core dependency cycles without changing generated artifact bytes or command projections.
- `rsp workspace prepare <work-ref>` creates or resumes one isolated worktree on the stable branch `rsp/<work-ref>` for an existing executable Change. Its local record is shared through Git common state rather than tracked `.rsp/` files, binds the source worktree, target branch, base commit, branch, owned path, and registered activities, and fails closed on unrelated branch, path, record, or worktree ownership.
- Core checks the effective `workspace.activation` before selecting isolation: `auto` permits the existing material-signal decision, `explicit` requires a current explicit workspace request, and `disabled` denies RSP workspace selection even when other signals are present. The CLI workspace command remains an explicitly invoked mechanical operation and configuration grants no mutation or cleanup authority.
- `rsp workspace inspect` returns bounded tracked, local-only, changed, and dirty path facts without interpreting frameworks, task runners, service names, project architecture, commands, effects, or readiness. Project-semantic decisions and execution remain with the active AI or human through host-native capabilities; the CLI exposes no universal workspace plan, preflight, or command-execution DSL.
- Workspace subcommands invoked with `--json` return one LF-terminated `{ command, ok: false, error: { code, message } }` document and a non-zero exit code for command failures. Expected safety rejections and missing workspace state never write stack traces or mixed prose to stderr in JSON mode; non-JSON rendering remains independently human-facing.
- `rsp workspace activity register` records one already-running PID with its stable process-start identity, an optional process group whose ownership matches that PID, and optional opaque exclusive resource names. Registration never starts or verifies project behavior, exposes lease tokens, or grants network, credential, external-state, deployment, or publication authority. `activity stop` and disposal revalidate process identity before signaling, fail closed rather than signal a reused PID or process group, and release cooperative leases through the exact recorded owner token. A competing registration never removes a stale lease opportunistically; it identifies the recorded activity cleanup required before retrying. Disposal still refuses dirty or unlanded state unless explicitly discarded.
- `rsp land <work-ref> --target <branch> --commits <sha[,sha...]>` accepts only ordered commits owned by the recorded workspace after its base and cherry-picks them into the exact recorded checked-out target. Existing Git operations and unsupported merge commits fail before mutation; conflicts preserve both source workspace and target cherry-pick state. Optional cleanup requires the complete workspace commit set, runs only after successful landing, and reports cleanup failure separately without concealing that landing succeeded.
- Change and Group Brief commands share one typed semantic document model for canonical identity headings and section lookup. The model retains original source offsets, unknown headings, and duplicate occurrences; consumers decide diagnostics and lifecycle consequences instead of a parser silently repairing structure.
- Reopen inserts unfinished Tasks and Verify evidence through exact semantic section spans and requires one occurrence of each target section. Canonical scaffold renderers consume the same structural vocabulary, while existing Markdown serialization and public command projections remain stable.
- `status`, `show`, `ready`, `check`, `doctor`, `specs`, and `history` preserve pretty `--json` output and accept `--json --compact` for the same value on one LF-terminated line. `--compact` without `--json`, or on another command, fails before command behavior.
- `rsp history` is a bounded archive query independent from the current-work status snapshot. It reads the complete authoritative archive tree, validates canonical safe Unicode identity and metadata fail closed, recognizes but omits Group Brief records, and orders Change records by archive date descending, WorkRef, then project-relative archive path.
- History requires a real archive root and rejects archived executable headings claiming reserved `brief` or `00-brief` identities. At most one canonical flat or one-Group-level Unicode WorkRef is accepted, before archive inspection in every output mode.
- History lists default to 20 results and accept 1–100 after inclusive date, exact historical kind, exact Group, and case-insensitive literal WorkRef/summary search filters. Empty search fails before archive inspection. Results expose matched/returned counts and `hasMore`; the first release has no cursor or offset.
- Open status and archive History share the same Change summary precedence. History preserves immutable archive compatibility for a retained `<…>` summary, retains its existing bounded output, and searches the complete untruncated semantic summary before applying its result limit.
- Exact history detail accepts a WorkRef or internal stable archive path. It returns bounded summary, scenario/checkbox counts, and bounded Tasks/Verify/Blockers evidence without raw Markdown. Duplicate generations of one WorkRef are ambiguous and return candidate paths.
- `rsp reopen <work-ref> --reason <text>` reuses complete fail-closed archive inspection and restores one archived executable Change to its canonical open path while retaining the archive. A unique WorkRef match is sufficient; multiple matches require exact `--from .rsp/archives/...` selection whose inspected identity matches the positional WorkRef.
- Reopen requires one non-empty single-line reason, exactly one canonical Tasks and Verify section, no existing open file or stale focus marker, and an open declaring Group Brief for grouped children. It creates the open file and focus marker under the RSP lock, rolls back a partially created Change when focus creation fails, and inserts unfinished Task and Verify items so readiness is no until the concern is resolved.
- Reopen never selects the newest archive implicitly, overwrites open work, mutates archive history, cascades into dependents, reopens a closed Group, or grants Git delivery. When open work and archives share a WorkRef, status and dependency projections treat the WorkRef as open current work.
- `rsp group reopen <group> --reason <text>` uses the same complete fail-closed archive inspection and exact `--from` disambiguation to restore one retained Group Brief at its canonical open path. It requires one canonical identity and each canonical Group section exactly once; the target Group work and focus subtrees must be absent or empty, so orphan children, stale focus, unsupported entries, identity mismatch, and open collisions all fail before mutation.
- The appended unchecked completion evidence binds the exact selected archive path to the one-line reason. Publication rejects an evidence key already present in any retained Brief snapshot. Status accepts same-identity continuation only while the open Brief contains at least one non-dropped evidence item whose embedded path exactly belongs to the current Group's retained Brief path set and whose key is absent from every retained snapshot. A nonexistent path, another Group's real Brief path, or a closed snapshot copied back into `changes/**` cannot masquerade as explicit reopen.
- Group reopen runs under the RSP lock and publishes from a same-filesystem hidden temporary file outside the inspected `changes/**` tree, so failed publication or temporary cleanup cannot expose status-invalid open work. It preserves the archive, creates no focus, and never reopens a child or dependent. `rsp group create` continues to reject any archived Group identity; callers separately reopen each incomplete child.
- History diagnostics and ambiguous candidates are each capped at 20 with total, returned, and `hasMore`. Human errors use the same bound and omitted count; archive read failures remain diagnostics rather than duplicate runtime output.
- `.rsp/archives/**/*.md` files are the sole authoritative archive records. CLI history, TUI History, and status archive trends share the complete fail-closed history inspection; no Archive Index is created, required, read, repaired, or diagnosed.
- History inspection and detail re-read current archive files only through their real `.rsp/archives` containment, no-follow open where available, pre/open/post file identity checks, and a 512 KiB per-file read bound. Replacement, symlink, growth, and oversize races fail closed before parsed history is returned.
- `rsp init`, `rsp update`, and `rsp doctor --fix` remove a legacy regular `.rsp/archives/INDEX.md` only when its YAML metadata is `kind: generated-index` plus `index_type: archives`; an unrecognized entry at that path is preserved.
- `rsp specs` derives deterministic tree, exact detail, and case-insensitive bounded literal-search projections directly from current regular Markdown. Results preserve project-relative source paths, document kind, title, summary or heading context, current checkout identity, explicit bounds, and bounded diagnostics.
- One presentation-neutral `src/specs/` seam is shared by CLI and available to the TUI presenter. It requires complete no-follow inspection, excludes the default or configured Decision Record subtree from current-fact Specs while identifying Decision Records separately, and re-applies file bounds when detail or search rereads current content.
- Search defaults to 20 results, accepts 1–100, bounds excerpts to 40–1000 Unicode code points, inspects at most 1000 candidate Markdown files of at most 512 KiB each, and returns deterministic source order with matched/returned/`hasMore` counts. Detail content is bounded to 12000 code points.
- `rsp init` and `rsp add spec` never create, require, or rewrite generated Specs indexes. `rsp update` and therefore `rsp doctor --fix` remove only reserved root `INDEX.md` or any `00-index.md` whose metadata is `kind: generated-index`, `index_type: specs`, and an exact owning-directory `source_dir`; all candidates and complete real project/Specs parent identities are preflighted and revalidated before every quarantine, copy, unlink, or restore, postchecked through direct Specs inspection, and restored through exclusive no-overwrite materialization with a byte/mode-verified copy fallback when hard links are unavailable. Parent swaps, concurrent targets, unrecognized, unreadable, replaced, or otherwise owner-controlled reserved content fail closed without overwrite or deletion.
- One `rsp update` invocation is a command-scoped rollback boundary for config, fallback, `AGENTS.md`, created directories/placeholders, legacy Archive Index, and generated Specs-index migration. A late failure restores original bytes, modes, and paths; if concurrent replacement prevents complete rollback, `doctor --fix` lists every retained mutation or recovery copy in `fixed` and reports the repair issue.
- `rsp doctor` reports recognized generated Specs indexes as an update-required migration issue, while direct `rsp specs` tree, detail, and search remain the navigation authority after removal.
- `rsp doctor --fix` reports only real filesystem mutations in `fixed`; an empty array means no safe repair changed files.
- The CLI exposes no Broker lifecycle, SQLite runtime-store, managed-runtime, or Web Observatory commands. Repository-native command behavior is derived from current files and checkout evidence without hidden runtime state.
- `durableReview.factCandidateTargets` reports likely writable fact owners and `durableReview.decisionRecordsPath` reports the authoritative rationale directory. Generated `00-index.md` files and bundled rules are excluded from ordinary writeback targets.
- `ready --json` and `show --json` expose deterministic readiness and semantic durable-review guidance without deriving archive actions.
- `.rsp/rsp-rules.md` is the only runtime fallback path. `rsp update` migrates and removes the obsolete generated `.rsp/rules/rsp-rules.md`; residual `.rsp/rules/` content is not authority and requires explicit semantic migration before removal.

## Boundaries
- In scope:
  - Command registration, deterministic config inspection, filesystem safety, status/check/doctor and Specs projections, archive queries, isolated workspace execution and local landing, and machine output.
- Out of scope:
  - Semantic completion judgment, hidden scheduling, automatic durable writeback, release authority, and interactive dashboard presentation.

## Constraints
- Plain and JSON projections must describe the same authoritative state and fail closed on incomplete inspection.
- Prefer stable machine-readable diagnostics that reduce guessing without adding workflow state or schema-heavy extension points.
- Managed paths are never followed through symlinks, and write preflight precedes partial mutation. Command input is normalized to NFC before identity resolution; discovered non-canonical or normalization-colliding stored paths fail closed and are never silently renamed.
