# Separate delegation from final-delivery closeout

The former Manage policy coupled coordination selection, lifecycle completion and
a limited local Git grant. That made completion too close to closure and made
ordinary continuation depend on an unnecessary coordination classification.

Use independent delegation and closeout policies. Default delegation is off and
closure asks at established final delivery; checkpoint commits retain open work.
User or main-agent judgment chooses worker count within host constraints. RSP
retains ownership, dependency safety and evidence obligations without numeric tiers.

Reject old manage configuration with an explicit migration diagnostic. A silent
mapping cannot preserve the old local Git grant while meeting the new rule that
closure never grants Git authority. Configuration owners must choose new values;
update leaves legacy input unchanged. JSON consumers must migrate too.

Keep knowledge writeback before final Change reconciliation, and reuse checks and
reviews while relevant inputs remain applicable. Review independence is distinct
from independently executing checks. Reopen remains available for exceptional
recovery rather than routine adjustments after premature closure.

The tradeoff is a deliberate configuration migration and a default closure question
at final delivery. These costs keep ongoing iteration open and make Git authority
explicit. Current contracts live in Work model, Workflow and CLI; this record owns
the rationale, not another policy definition. Model efficiency remains unverified.
