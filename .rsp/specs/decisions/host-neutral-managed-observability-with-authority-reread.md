# Use host-neutral managed observability with current-authority reread

RSP exposes optional managed-run observability through a host-neutral adapter because hosts need exact run, dispatch, event, receipt, attention, pause, resume, and context correlation without turning the Broker, SQLite store, or retained runtime data into a scheduler or workflow authority.

## Considered Options

- Persist managed control state under `.rsp/`: rejected because routes, frontiers, worker envelopes, receipts, acceptance, and continuation are transient contracts, while repository state must remain limited to current work, durable facts, rationale, scoped instructions, and archives.
- Parse worker prose or conversation transcripts into runtime events: rejected because narration is localized, incomplete, and not an authenticated source of dispatch, worker, result, authority, stop, or acceptance identity.
- Let the runtime create workers, choose lanes, retry, resume, or derive acceptance: rejected because those actions belong to the host, Core, Manage, and the owning Discipline contracts; a hidden scheduler would widen authority and duplicate canonical control semantics.
- Require Broker and SQLite for Manage: rejected because published Skills must remain host-neutral and ordinary managed execution must preserve exact no-runtime behavior.
- Reuse a context packet without rereading authority: rejected because checkout, WorkRef, Git, dirty paths, authority, and source identity can drift independently of retained observations.

## Consequences

- The package ships `dist/manage-runtime.mjs` with capability identity `rsp.manage-runtime@1.0`. It may use a direct accepted event store or project-token-scoped Broker protocol `1.2` endpoints, but discovery never starts a Broker implicitly.
- Run correlation begins only after Manage validates the selected handoff. Dispatch correlation is recorded only after the host creates a real worker and returns exact dispatch and worker identities; structured events and receipts must match those identities.
- Every new run, dispatch, event, receipt, attention, pause, resume, or terminal observation advances one transactional committed run sequence. Duplicate delivery retains one committed effect at its original sequence. Worker events require an existing dispatch and exact worker identity. Missing, unavailable, or boundary-changing receipts remain incomplete and may produce bounded attention; no prose parser or projection manufactures success, acceptance, review, or closeout.
- Run and attention projections return at most 32 items, are explicitly non-authoritative, and read their committed revision plus rows from one short SQLite snapshot with exact source references. The narrow `terminalDeliveryObserved` field additionally requires an explicit host terminal boundary at the current committed revision, at least one dispatch, no truncation, and safe retained delivery for every observed dispatch; any later committed observation clears it until a new terminal boundary and it is never managed acceptance.
- Managed context packets use one fixed key, remain within 12 KiB and 24 hours, and exclude prompts, hidden reasoning, complete output, credentials, tokens, and unbounded logs. Public save and hydrate requests expose no caller-controlled clock; the runtime service owns update, expiry, and hydration time.
- Context save compares its expected source sequence with the current committed run revision inside the same short write transaction as packet version ownership and persistence; a stale save is returned as not applied. Resume compares the retained packet sequence again, then validates checkout, WorkRef, Git, dirty paths, authority, expiry, and complete source identities. Fresh or selectively stale packets may reuse only unchanged evidence summaries while authority and changed sources are reread; a later committed observation, authority or checkout drift, absent runtime, expiry, or fully stale context requires reread or rebuild.
- Runtime absence, incompatibility, corruption, disposal, or observation failure remains a bounded diagnostic. Current repository authority and the canonical Core, Manage, Discipline, acceptance, closeout, lifecycle, Git, publication, and human-acceptance contracts always win.
