# Use fragment bootstrap and one bundled React root for the local Web Observatory

RSP uses one short-lived, one-use URL-fragment bootstrap to establish a project-scoped in-memory Web bearer, and renders the complete Observatory through one typed React root compiled into an exact local browser bundle.

## Considered Options

- Put the Broker project token in a query string or cookie-setting navigation: rejected because the credential could enter browser history, Referer values, access logs, screenshots, copied normal command output, or unrelated same-origin requests.
- Put the project token directly in the URL fragment: rejected because the browser would retain the long-lived checkout-session credential even though fragments are not sent to the server.
- Serve one unauthenticated project page and rely on loopback secrecy: rejected because another local process or page that learns a project identity could read checkout projections.
- Start one authenticated HTTP server per checkout: rejected because it would duplicate endpoint discovery, process lifecycle, idle ownership, security policy, and multi-worktree isolation already owned by the user-level Broker.
- Keep the original framework-free string renderer: rejected after the Observatory grew to five views, localization, automatic refresh, SSE recovery, cancellable detail/search requests, responsive master-detail layouts, and compatibility fallbacks. Continuing with whole-page string replacement would make the planned parallel visualization and structured document presentation harder to isolate and verify.
- Add a client router, state-management framework, React Flow, or runtime-loaded chunks: rejected because one local root, reducer-style transitions, React state/effects, and deterministic native presentation components cover the evidenced interaction boundary without another authority or asset-loading layer.
- Parse Markdown in the browser or send generated HTML: rejected because either choice would move repository interpretation into the untrusted presentation process or create an avoidable HTML-injection surface. The server instead maps a direct CommonMark parser result into a repository-owned bounded JSON projection after redaction and source bounding.

## Consequences

- `rsp web` requires current Broker protocol `1.3`; its Web route and bootstrap contract were introduced in protocol `1.1`, managed observability arrived in `1.2`, and complete-document response plus static-asset bounds became compatibility-relevant in `1.3`. It explicitly starts or reuses that compatible Broker, registers the exact checkout, and asks the authenticated project session to mint one bootstrap that expires after one minute and is consumed at most once.
- The bootstrap appears only in the URL fragment. The static shell contains no project data, the fragment is not sent in the initial request or Referer, browser code removes it before API access, and only an exact-origin POST may exchange it.
- Bootstrap exchange creates a separate project-scoped Web bearer held only in page and Broker memory. It is neither repository state nor browser storage, expires after eight hours, is discarded on session unload, and cannot authorize control or ordinary project-token routes.
- Normal human and JSON command output contains only the credential-free project URL. An explicit interactive `--print-url` or interactive browser-open failure may reveal the expiring one-time bootstrap as a human fallback; redirected non-interactive output never receives it.
- The package ships exact no-follow `web/static/index.html`, `app.css`, and generated `app.js` assets plus `dist/web-projector.mjs`. Typed sources under `web/src/` are build inputs and are not packed. The stable ESM bundle contains React 19 and React DOM and has no shebang, source map, remote import, runtime chunk lookup, checkout path, repository data, token, or environment configuration. The Broker retains separate 1 MiB HTML, 2 MiB CSS, and 8 MiB JavaScript package-integrity limits. They preserve bounded identity-checked reads without turning ordinary UI growth into a compatibility failure.
- One `createRoot` owns the complete page. React components receive explicit browser state and callbacks; they do not inspect repository configuration, parse Markdown, inject generated HTML, or derive workflow authority. Specs detail components render only the server-owned block and inline union, switch locally between rendered and exact safe-source modes, and represent omitted or bounded content explicitly. Runs defaults to a deterministic native invocation tree keyed by exact `dispatchId`; repeated calls remain distinct, optional worker display names and roles remain labels, and parent-child nesting uses only the projected exact parent invocation relationship. The secondary Sequence mode retains the native SVG committed-sequence graph and synchronized textual timeline, while Raw events exposes bounded source observations for exact audit inspection. These views do not use timestamps for order, merge invocations by worker labels, infer unresolved ancestry, derive identity or acceptance, or add a graph-layout dependency. Bootstrap exchange, in-memory bearer handling, snapshot replacement, SSE replay, automatic refresh, locale switching, view-local failures, stale recovery, and earlier-Broker History compatibility remain browser coordination behavior.
- The bundled browser catalog owns complete `en` and `zh-CN` presentation labels, resolves supported browser preferences with deterministic English fallback, and permits a session-local language switch. Repository WorkRefs, paths, canonical values, diagnostics, evidence, and projected source content are never translated, and browser locale does not read project artifact or commit language configuration.
- The Browser renders complete safe server projections for every Specs or archived Change document accepted by the identity-checked 512 KiB file boundary and never parses Markdown semantics. The server permits headings, paragraphs, emphasis, strong text, inline and block code, lists and task markers, blockquotes, thematic breaks, and bounded `http`, `https`, or `mailto` links; raw HTML, images, unsafe destinations, excessive nesting, and unknown syntax cannot become executable elements or additional resource requests. Specs and History share one rendered/source React presenter, and the 16 MiB JSON ceiling remains an abnormal-input guard rather than a normal truncation path. Successful refresh atomically replaces one complete snapshot; failed or incompatible refresh preserves the previous snapshot as visibly stale with a bounded redacted error.
- Exact loopback, Host, request-target, Origin, method, path, query, token, response-size, redaction, Content Security Policy, no-store, no-referrer, frame, MIME, and Permissions Policy checks remain one Broker-owned boundary.
- A future remote binding, cookie session, persistent browser storage, service worker, inline script, mutation route, runtime-loaded asset graph, or hosted/multi-user product must revisit authentication, origin, packaging, CSP, retention, and authority together.
