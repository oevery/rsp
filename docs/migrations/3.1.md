# Migrating to RSP 3.1

## Durable language policy

RSP 3.1.0-beta.4 adds one strict project language mapping for durable shared prose:

```yaml
language:
  default: en
  # artifacts: zh-CN
  # commit: en
```

`language.default` supplies both artifact and commit prose unless a surface-specific override is present. Response language remains owned by the current user, host instructions, and conversation; `language.response` is unsupported and makes the mapping fail closed. Existing artifacts are never translated automatically, and canonical headings, commands, WorkRefs, paths, Conventional Commit types/scopes, trailers, and machine values remain unchanged.

CLI-created Change, Group Brief, project-setup, and Spec scaffolds now use neutral `<…>` placeholders with canonical structural tokens and verbatim user-supplied summaries or goals. Fill their natural-language prose according to project authority; do not translate the canonical protocol headings.

## Unicode WorkRefs

WorkRefs may use lowercase or caseless Unicode letters, marks, and decimal numbers separated by internal hyphens. Each segment is normalized to NFC and bounded by both Unicode code-point and UTF-8 byte length. ASCII lowercase kebab-case remains fully compatible.

RSP never silently renames existing paths. A non-canonical stored name, normalization collision, unsafe punctuation, unsupported depth, or ambiguous Unicode identity fails closed for owner review. Before adopting Unicode names in an existing project, run `rsp doctor` and `rsp check` and resolve any reported stored-path conflicts explicitly.

## Automatic Manage routing and worker delegation

Projects using `manage.activation: auto` should expect beta.4 to select Manage more proactively. A selected ready completion or continuation stays direct only when it has one owner, one local seam, one mutation pass, one decisive check, no managed lifecycle coordination, and no ready successor; if any condition is false, it is treated as managed non-small work. Later implementation that expands an earlier report, design, tiny, or small route is requalified before mutation.

When workers are available and authorized implementation remains, qualified Manage delegates at least one implementation worker. This does not imply parallelism: shared paths, generated artifacts, providers, real hosts, hardware, and dependent verification stay sequential unless mutation and verification resources are both isolated. Automatic selection still grants no planning, mutation, lifecycle, Git, push, publication, deployment, approval, or human-acceptance authority.

Refresh package-owned Skills separately after updating the CLI:

```bash
rsp update
rsp skills install --dry-run
rsp skills install
```

## Canonical document compatibility

The new semantic document model is internal. Persisted Change and Group Brief headings remain canonical English protocol tokens, and existing Markdown does not require migration. RSP preserves unknown content and surgical edits outside owned section spans; localized or near-match headings do not become aliases.

## Archive history

RSP 3.1 removes the generated `.rsp/archives/INDEX.md`. Archive Markdown remains authoritative and `rsp history`, TUI History, and status archive trends inspect it directly.

Run `rsp update` from the project root. The update removes `.rsp/archives/INDEX.md` only when the regular file has `kind: generated-index` and `index_type: archives` metadata. An unrecognized file or unsupported filesystem entry at that path is preserved for manual ownership review.

Use `rsp history --search <text>` for a bounded case-insensitive literal match over WorkRef and summary. Search composes with date, kind, Group, limit, human, JSON, and compact output.

## Hierarchical Specs navigation

RSP 3.1 replaces the recursive `.rsp/specs/INDEX.md` projection with generated per-directory `00-index.md` navigation. Each index lists only direct child Specs and populated child Spec directories; the Decision Record subtree is excluded.

Run `rsp update` to reconcile the complete hierarchy. A legacy root `INDEX.md` is removed only when `kind: generated-index` and `index_type: specs` prove RSP ownership. Unrecognized content at a reserved index path is preserved and reported for manual ownership review. After migration, use the root `.rsp/specs/00-index.md` and descend through local indexes; do not edit generated index bodies.

## Skill identity migrations

RSP 3.1 replaces the published `rsp-address-review` Skill with `rsp-resolve-findings` and the optional `rsp-codebase-audit` Skill with `rsp-structural-audit`. Current routing and installation use only the replacement identities; retained archives and evaluation provenance keep the names observed at their original revisions.

Preview the exact package-owned migration before authorizing removal of obsolete real directories:

```bash
rsp skills install --dry-run --force
rsp skills install --force
```

Without `--force`, installation stops before mutation when an obsolete package-owned directory exists. Force installation removes it transactionally with replacement activation and restores it if activation fails. Symlinks, special files, and unrelated project Skills are never treated as obsolete package-owned directories.

## Archive readiness command

Use `rsp ready <work-ref>` for the canonical read-only archive-readiness projection. `rsp archive <work-ref> --dry-run` remains available as a deprecated compatibility route to the same human result; it does not archive the Change.
